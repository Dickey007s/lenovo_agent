# 规则数据与评测资产使用说明

## 使用顺序

1. 先阅读 `四边界风险映射_自主等级修正版/四边界风险等级自主等级映射表_自主等级修正版.md`，确认现行等级语义。
2. 用 `P0_Demo_Fixtures/schemas/action_spec.schema.json` 校验模型生成的 ActionSpec。
3. 用 `fixtures/policy_rules.json` 和 `fixtures/privacy_rules.json` 实现确定性规则下限。
4. 用 `fixtures/risk_examples.json` 做 few-shot/检索辅助，不让模型直接放行工具。
5. 用 `fixtures/eval_cases.json` 做固定回放和规则回归。
6. 用 `fixtures/task_snapshots.json`、`mock_contexts.json` 和 `audit_log.json` 串三个 Demo。

## 版本关系

`四边界风险映射_自主等级修正版` 是 2026-06-08 的最新口径，优先于 2026-06-04 P0 fixtures 的原始映射。为保证活动资料库可直接使用，本目录中的 fixtures 副本已完成以下修正：

- `policy_rules.json`：修正 L2、L3、L4 的 Human Gate 自主等级。
- `risk_examples.json`：73 处样例标签统一到现行映射。
- `eval_cases.json`：63 处预期自主等级统一到现行映射。

历史压缩包原件未修改，仍保留在 `7.16前_过程文件`。

## 当前数据规模与限制

- 风险示例约 95 条，可用于 P0 演示，不足以代表生产分布。
- 当前数据为模拟办公数据，不包含真实企业用户和业务记录。
- 规则适合验证架构，不应直接作为生产合规策略。
- 下一阶段应扩充到至少 300 条固定评测样本，并为每条规则增加单元测试。
- 生产接入前需要由法务、安全、财务、人事和业务负责人共同确认硬规则。

## P0 验收重点

- 相同 ActionSpec、规则版本和设备上下文必须得到相同结果。
- L4/L5 漏判率和 L5 越权执行率为 0。
- L3—L5 审计覆盖率为 100%。
- 密码、验证码、Token、密钥入模率为 0。
- 模型超时、非法 JSON、关键字段缺失时必须安全回退。
