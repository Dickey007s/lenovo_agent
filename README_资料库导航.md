## 当前最重要的技术框架

### 1. 动作级 Risk Gate

```text
UserEvent
→ Context Adapter
→ Privacy & Permission Guard
→ Intent / ActionSpec Parser
→ Example Retriever + LLM Risk Judge
→ Rule Engine + Decision Fusion
→ Human Gate
→ PanelSpec
→ Tool Executor / Simulator
→ Audit Logger + Feedback Loop
```

该框架是下一阶段最重要的工程主线。模型只负责理解和建议，企业规则、权限和 Human Gate 决定是否执行。

### 2. 风险等级 × 自主等级 × 四边界

安全边界决定“能不能做”，接管边界决定“谁来做”，透明度边界决定“执行前解释什么”，效率边界只在前三项允许的范围内优化。这套框架直接决定三个 Demo 中每个动作的 UI 和工具权限。

### 3. 跨端 TaskSnapshot

PC 保存完整任务状态，手机只接收轻量、脱敏的继续卡片，返回 PC 后做版本校验、恢复和草稿插入。下一阶段要把它落实为 TaskSnapshot Schema、同步状态机和版本冲突策略。

### 4. 多任务状态机与 Agent 编排

任务驾驶舱不是待办列表，而是带依赖、优先级、风险、资源锁、确认点和异常恢复的任务图。下一阶段需要在此基础上补 8 子智能体分工、动态路由和焦点/资源仲裁。

### 5. 受控 GenUI / PanelSpec

模型不直接自由生成高风险界面，而是输出结构化 PanelSpec，由固定组件渲染 Toast、草稿卡、确认卡、Risk Lens 和拒绝卡。这样能兼顾个性化、界面稳定性和审计。
