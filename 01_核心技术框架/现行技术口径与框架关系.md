# 现行技术口径与框架关系

## 主架构

下一阶段以动作级 Risk Gate 为实现主线：

```text
入口层：UserEvent
上下文层：Context Adapter + Privacy & Permission Guard
理解层：Intent Parser + ActionSpec Parser
建议层：Example Retriever + LLM Risk Judge
裁决层：Rule Engine + Decision Fusion
共驾层：Human Gate + PanelSpec
执行层：Tool Executor / Simulator
治理层：Audit Logger + Feedback Loop
```

## 模型与规则边界

- 模型负责意图理解、结构化候选、风险建议、草稿和解释文案。
- Schema 负责约束字段、枚举、必填项和非法输出。
- 企业规则负责风险下限、禁止动作、权限和隐私硬门槛。
- Decision Fusion 取更保守结果；模型不能降低硬规则等级。
- Human Gate 决定工具是否可调用；L3 以上必须先进入接管状态。

## 现行等级映射

| 风险 | 自主 | 处理方式 | UI |
|---|---|---|---|
| L0 | AL5 | 后台自动 | 日志 |
| L1 | AL4 | 自动执行、可撤销 | Toast + Undo |
| L2 | AL3 | 生成草稿、不写系统 | 草稿卡 + 来源 |
| L3 | AL2 | 预览确认后执行 | 确认卡 / Diff |
| L4 | AL1 | 风险建议、强确认 | Risk Lens |
| L5 | AL0 | 拒绝自动执行、转人工 | 拒绝卡 / 人工入口 |

## 三个 Demo 与主架构的关系

- Demo 1 重点验证 Context Adapter、Privacy Guard、TaskSnapshot、跨端 PanelSpec 和版本恢复。
- Demo 2 重点验证任务图、子 Agent 编排、并行准备、确认队列和异常恢复。
- Demo 3 重点验证 ActionSpec、规则融合、Human Gate、Risk Lens、拒绝卡和审计回放。

三个 Demo 不应各自建立一套后端。它们共享同一套事件、上下文、动作、风险、接管、界面和审计协议，只替换场景数据、任务图与工具模拟器。
