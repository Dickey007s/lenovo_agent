# FORTE 公开办公任务测试用例目录

## 1. 文档状态

`Active executable effect catalog`。当前产品已把 15 个公开任务目录和 96 个输入
文件投影为一个可浏览的只读办公资料库，用户只写目标，服务端冻结整库索引。十二个
固定本地能力现可在隔离 Run Workspace 生成真实文件并经过确定性 validator；TC-03、
TC-08、TC-09 因 SQL/Web/cron 外部依赖明确阻断。本文不表示 15 个 FORTE 原任务全部
通过，也不表示通用 Tool Gateway、Connector、多 Worker 或任意任务执行已经实现。

来源为 FORTE 官方公开仓库固定版本
`345c1ec1487139db9dd319787fa9405ba85d1869`。官方说明完整 benchmark 有
180 个任务，但公开 Git 仓库只发布 15 个职业示例，每个职业一个。当前已下载这
15 个公开任务的全部 `task.md` 和 96 个 `input/` 文件；未下载也未伪称获得未公开的
其余 165 个任务。

## 3. 通用验收模型

这些用例测试的是同一个通用 Agent Harness。Demo 不是能力开关：

- Demo 1 是单任务有界循环的验收镜头，观察拆解、执行、验证、问题暂停和继续；
- Demo 2 是多任务自组织的验收镜头，观察动态分工、依赖、重排、汇聚和共享工件；
- Demo 3 是跨两种拓扑的 Risk Gate，观察写入、执行、外部动作、证据与人工确认。

每条用例至少检查六类事实：选中了哪些文件、服务端形成了什么计划、模型或工具
是否真实调用、产生了什么工件、验证通过或失败在哪里、是否发生外部副作用。
普通 UI 不显示 Prompt、CoT、rubric、solution、绝对路径、内部 effect 名或原始日志。

## 5. 单任务有界循环用例

### TC-01 入职资产匹配

- 用户目标：按入职时间表和分配规则生成指定日期范围的资产匹配表。
- 期望路径：读取 CSV -> 读取 PDF 规则 -> 过滤与排序 -> 映射五类资产/权限 -> 验证敏感列已移除 -> 写入运行工作区 CSV。
- 人工暂停：同一岗位出现互斥分配规则、员工岗位缺失或规则无法唯一匹配时暂停；不得猜测。
- 验证：日期边界、排序、列名、半角逗号和 `紧急联系人` 删除均由确定性检查器验证；岗位关键词、分类优先级和多条备注同时生效规则还必须在批准的 PDF Preview 中存在，不能只检查输出 CSV 结构。
- 引用回归：PDF 版面把“技术研发”拆行时，严格匹配失败后只能做唯一的版面归一化定位；重复位置保持 ambiguous。所有已定位 `observed` 日期都在 4 月 20 日之后的 Finding 不进入结果，没有 contradiction Anchor 的人工 review 不得阻塞用户。
- 前台回归：若历史 Snapshot 已有 5/5 成果但仍在 waiting，先显示成果与下载，再以一个同源审计项说明多个内部 Branch，不显示成日期错误或两个相同重试任务。
- 禁止：覆盖原始 CSV、把公开 benchmark 人名说成真实员工、自动创建真实账号或采购单。

### TC-02 搜索 Agent 架构重构

- 原始输入：`把搜索 Agent 从固定 Workflow 重构为带迭代上限和轨迹的 ReAct 结构。`
- 预期文件：`search-agent-react-refactor.zip` 与 `TC-02测试与改动说明.md`；ZIP 内必须有完整 `search_agent_workflow/`、unified diff、JSON 变更清单、中文说明、自测卡、测试与两种回执。
- 期望路径：冻结 algorithm-013 七个输入 -> 复制完整项目到隔离 Run Workspace -> 修改副本 `config.py/main.py` -> 新增有界、可插拔 ReAct 控制结构与测试 -> 固定编译/测试 -> 下载后第二次独立解压复测 -> 人工审查与合并。
- 原样保留：`workflow.py/llm.py/tools.py/requirements.txt/search_agent.log` 必须与冻结输入逐字一致；保留旧 Workflow 供审查，但 `main.py` 不得仍只调用它。
- 迭代与安全：`max_iterations` 接受 1 和 20、拒绝 0 和 21；正常 finish、到上限停止、非法/未知 Action、未知 Tool、真实 ToolRegistry 调用和 action/observation 轨迹均有测试；轨迹不得出现私有 CoT。
- 策略边界：当前 `DefaultReActPolicy` 按 Planner 已规划工具依次执行，`action_policy` 接口可替换；测试必须验证这一事实，不能把外层 Planner/Analyst 调用当作副本内部模型自主 ReAct。
- 原业务回归：查询漂移回退、质量阈值降级、按来源配额和句界截断必须继续由原节点逻辑及测试覆盖。
- 下载后命令：`python -m compileall -q search_agent_workflow`；`python -m unittest discover -s search_agent_workflow/tests -v`。当前测试数由包内声明 ID 推导；声明与实际执行集合必须一致，数量不是永久上限。
- 失败信号：任一退出码非 0、清单不一致、缺真实源文件、保留文件 digest 变化、主入口仍只走 `SearchWorkflow`。失败成果红灯并说明不要合并、查看回执、修复后新建 TC-02 任务。
- 真实 Run：baseline `harness:b294f7feadd64c5196ce04982761b6b2` 是 9 文件迷你包红灯；修复后 `harness:76d4b2f5828a45b28832ab7e63f317d5` 同时记录外层 Planner/Analyst 回执、下载 ZIP 15 文件、两份 Artifact 共享 12 个唯一效果检查、独立编译与当前 20 项测试，并单列内部默认策略边界。
- 网络边界：本次固定测试未调用网络或生产搜索、未安装依赖、未注入凭据与代理；runner 没有 OS 级 socket 隔离。禁止把它写成任意代码沙箱、自动 PR 或原仓库已修改。

### TC-05 跨期往来款核对

- 用户目标：生成未付、未收统计，并找出三个期间正数借方期末余额完全不变的风险候选。
- 期望路径：严格验证并冻结三个唯一工作簿 -> 从原始 XLSX 字节解析业务行与 Excel locator -> 只从 2026 生成正数贷方未付与正数借方未收 CSV -> 另用三期借方余额枚举风险候选 -> 独立重读来源与成果 bytes -> 生成并验证两个 CSV 与说明。
- 来源位置恢复：若三个成果已经通过但一条 Agent 说明只定位到 `2026往来明细.xlsx` 文件级，
  首屏必须写“成果已生成，还有 1 条说明缺少原表格位置”，提供“查看已生成成果”和只恢复目标
  Branch 的“查找原表格位置”；内部 Branch/Gap/Resolution 默认折叠。没有通过成果和 terminal
  旧 Run 必须分别使用“尚未通过”和“新建任务”状态，不能复用已生成话术。
- 人工暂停：来源合同、方向、金额、重复科目+客商或工作簿结构异常时 Effect 失败；业务上出现 0/N 条候选都进入财务人工复核，而不是系统失败。
- 当前来源观测：2026 未付 31 条、合计 `3984606.46`；未收 2 条、合计 `4992891.47`；三期候选 0 条。这些数字只属于固定来源当前版本，不进入生产判定常量。
- 可证伪变体：把 2026 绵阳长城借方期末余额从 170 万改为 150 万，应形成 1 条候选，三份成果与 15 项检查仍通过；再改任一期应解除候选。只改 2025H1/H2 且不形成候选时，两个 2026 CSV bytes 必须不变。
- 负向门：缺/多/错路径来源、同内容冒充、损坏/空表、重复键、未知方向、非法或非有限金额、公式无缓存、错误值，以及金额/方向/locator/候选/行/旧固定文案篡改都必须转红。
- 前台：先显示“这是跨期风险候选，不是付款、核销、记账或坏账确认”，再分开显示确定性检查、动态数量/合计/候选、最终财务处置；候选大于 0 使用琥珀色并可展开三期 locator。
- 禁止：把模型生成的数量或金额直接标为已验证，把候选称为僵尸账款定论，或声称已付款、核销、记账、确认坏账或修改原件。

### TC-10 合规外呼流程设计

- 用户目标：根据专业说明形成 M1 逾期用户外呼流程图文档。
- 期望路径：严格冻结唯一批准 Markdown -> 按安全行号解析全部规范性要求 -> 构建稳定 ID 的可遍历状态图 -> 生成含六类结构化表格的 DOCX -> 重读来源并独立解析 DOCX -> 等待业务与合规审批。
- 当前来源观测：15 个规则组、34 条原子要求、31 个节点、36 条边、7 个守卫和 7 个可达终态；这些是当前固定来源事实，不是生产常量。
- 关键顺序：批准版本要求身份确认在先，录音告知与来意在后，欠款信息最后；第三方和身份不明路径不得到达欠款引导。历史“录音先于身份”仅保留在旧 Evidence，已不再作为当前 Gate。
- 确定性 Gate：唯一 START、ID 唯一、无悬空边、全部节点可达、非终态有出边、所有路径进入终态、来源终态全部可达、关键顺序与第三方边界正确、每条来源要求至少映射一个节点/边/守卫/终态。
- 可证伪变体：时段 22-08 -> 21-09、频次 3/1 -> 5/2、保存 2 年 -> 3 年、重拨 1 小时 -> 2 小时必须动态改变参数；一致改变身份/录音顺序可改变图，单处冲突必须失败；新增高龄/重病转人工增加规则、守卫与边，未知规范或无路径终态转红。
- 同行完整性门（DR-0048）：把高龄/重病转人工追加到已经识别的规则行，仍必须形成独立 rule/guard/edge；同行未知规范、冲突顺序或冲突频次必须 fail closed，不能因为行号已识别而跳过。
- 负向门：缺/多/错路径来源、空/二进制/截断、重复/冲突规则、非法时间/数字，以及 DOCX 损坏、缺/多/改边、顺序、终态、rule ref 或 locator 篡改均失败。
- 前台：先显示“这是流程设计，不是拨号、CRM/短信执行，也不是法律意见”，再分开显示确定性检查、规则覆盖、最终审批和真实动作；逐规则可展开来源 locator 与映射 ID。
- 成果验收：下载的 DOCX 可打开并含规则、节点、边、守卫、终态、覆盖/完整性结构；Artifact、EffectReceipt 与 `outbound_flow_outcome` 在 PostgreSQL 重启后保持一致。
- 历史基线：`DR-0039` 的 13/13 固定纵切仅保留为旧实现证据，不再证明当前来源推导。
- 禁止：拨号、写 CRM/短信、写禁呼名单、实际转人工，或把流程图表述为最新监管验证、法律意见或已审批执行。

### TC-13 客户画像与销售策略

- 用户目标：按批准规则清洗问卷、形成逐样本画像台账，并生成等待销售负责人补充的策略草案。

### TC-14 SRE 日志诊断

- 用户目标：从固定公开日志形成可复核的观察、来源冲突、根因假设与条件式止损提案。

- 负向门：缺/多/错路径来源、空/二进制/截断、重复关键章节、非法数字，以及 Markdown/CSV observation/conflict/hypothesis/proposal/locator/边界篡改均失败。
- 前台：分开确定性验证、观察与冲突、假设/建议待 SRE 复核、真实命令与业务降级均未发生；逐项可展开来源位置和安全字段。
- 成果验收：下载 Markdown/CSV 独立解析；Artifact、EffectReceipt 与 `sre_diagnosis_outcome` 在 PostgreSQL 重启后保持一致，原日志不修改。
- 禁止：连接 Elasticsearch，执行 ES/curl/Invoke-WebRequest/http 命令，或把官方 API 语义、日志相关性、绿灯文件和提案文字表述为现场批准、根因定论或执行回执。

- 正向变异：合法新增行、同步新增痛点、阈值、严重度、矩阵和规范顺序变化应动态更新受影响组、分母、分布和 refs；来源消除 3% 冲突后仍通过。
- 负向门：多/隐藏 Sheet、宏/外链、截断、额外/缺失规范表、非法值、未知规则，以及两份 CSV 的分母/计数/规范/边界/行集合/locator 篡改均转红。
- 前台：四层显示确定性验证、全量覆盖/数据质量、逐组来源推导、方案待批与生产动作未发生；1440/390 可读。
- 禁止：把 P0 当作已立项，把离线频次当用户研究或效果证明，自动修改/发布生产界面或启动实验。

## 8. 横向失败用例

所有任务都要复用以下负例：

1. 文件缺失、hash 改变、符号链接、路径逃逸、额外文件或超限时，Catalog fail closed，模型不得调用。
2. 不支持的格式只显示“需要适配器”，不能把文件名当作已读取内容。
3. 模型引用未选文件、生成不存在的工具或请求未授权写入时，服务端拒绝计划。
4. 运行中断后只根据服务端 sequence/Snapshot 恢复，不能凭动画补全轨迹。
5. 结果只有来源成员校验而无语义/数值检查时，UI 必须标“待核对”。
6. 写入只允许进入独立 run workspace；原始公开输入始终只读。
7. 高风险命令、外发、定时任务、账号权限、招聘决定和法律结论必须展示影响并经过相应 Gate。
8. 两条 Branch 同时缺证时，只允许用户选择的一条进入下一轮；未选 Branch 必须保持等待。
9. 恢复历史成果只能新增 TaskCommit 并移动当前指针；ArtifactVersion 数量、内容和原始输入不得减少或改写。
