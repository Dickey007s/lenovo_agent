# FORTE 公开办公任务测试用例目录

## 1. 文档状态

`Active test catalog`。当前产品已把 15 个公开任务目录和 96 个输入文件投影为
一个可浏览的只读办公资料库，并能在用户选择的文件范围内发起自由任务。本文仍不
表示 15 个 FORTE 原任务均执行成功，也不表示 task-specific validator、文件写入、
代码执行或外部 Connector 已实现。

来源为 FORTE 官方公开仓库固定版本
`345c1ec1487139db9dd319787fa9405ba85d1869`。官方说明完整 benchmark 有
180 个任务，但公开 Git 仓库只发布 15 个职业示例，每个职业一个。当前已下载这
15 个公开任务的全部 `task.md` 和 96 个 `input/` 文件；未下载也未伪称获得未公开的
其余 165 个任务。

## 3. 通用验收模型

这些用例测试的是同一个通用 Agent Harness。Demo 不是能力开关：

- Demo 1 是单任务有界循环的验收镜头，观察拆解、执行、验证、问题暂停和继续；
- Demo 2 是多任务自组织的验收镜头，观察动态分工、依赖、重排、汇聚和共享工件；
- Demo 3 是跨两种拓扑的 Risk Gate，观察写入、执行、外部动作、证据与人工确认。

每条用例至少检查六类事实：选中了哪些文件、服务端形成了什么计划、模型或工具
是否真实调用、产生了什么工件、验证通过或失败在哪里、是否发生外部副作用。
普通 UI 不显示 Prompt、CoT、rubric、solution、绝对路径、内部 effect 名或原始日志。

## 5. 单任务有界循环用例

### TC-01 入职资产匹配

- 用户目标：按入职时间表和分配规则生成指定日期范围的资产匹配表。
- 期望路径：读取 CSV -> 读取 PDF 规则 -> 过滤与排序 -> 映射五类资产/权限 -> 验证敏感列已移除 -> 写入运行工作区 CSV。
- 人工暂停：同一岗位出现互斥分配规则、员工岗位缺失或规则无法唯一匹配时暂停；不得猜测。
- 验证：日期边界、排序、列名、半角逗号和 `紧急联系人` 删除均由确定性检查器验证。
- 禁止：覆盖原始 CSV、把公开 benchmark 人名说成真实员工、自动创建真实账号或采购单。

### TC-02 搜索 Agent 架构重构

- 用户目标：把固定 Workflow 搜索代码改成有迭代上限和轨迹的 ReAct 结构。
- 期望路径：索引代码 -> 形成改造计划 -> 修改运行工作区副本 -> 执行测试 -> 分析失败 -> 有界修复 -> 输出变更与测试报告。
- 人工暂停：依赖安装、网络访问或超出允许命令集合时确认；测试持续失败达到预算时停止。
- 验证：原固定五节点路径不再是唯一流程，最大迭代可配置，Action 解析和轨迹测试通过。
- 禁止：在普通 UI 暴露模型 CoT；未经许可修改原始 benchmark 文件。

### TC-05 跨期往来款核对

- 用户目标：生成未付、未收统计，并找出三个期间余额完全不变的僵尸账款。
- 期望路径：冻结三个工作簿 -> 分期解析 -> 科目/客商归一 -> 汇总 -> 跨期比较 -> 数值验证 -> 生成两个 CSV 与说明。
- 人工暂停：科目符号、期末余额定义或客商映射出现冲突时只停相关分支。
- 验证：逐行公式、排序、跨期三元组和总额必须由确定性计算复核；引用只证明来源范围，不证明算术正确。
- 禁止：把模型生成的数量或金额直接标为已验证。

### TC-10 合规外呼流程设计

- 用户目标：根据专业说明形成 M1 逾期用户外呼流程图文档。
- 期望路径：抽取强制规则 -> 构建状态机 -> 检查六个终态 -> 生成 DOCX -> 规则验证。
- 人工暂停：规则互斥或缺失时进入 Evidence Gate。
- 验证：时段、录音告知、态度分支、转人工、重拨上限和六个终态全部可达。
- 禁止：拨号、写 CRM、发送短信，或把流程图生成表述为真实外呼发生。

### TC-13 客户画像与销售策略

- 用户目标：按规则清洗问卷、完成画像分类并生成差异化策略。
- 期望路径：读取规则和 CSV -> 清洗 -> 分类 -> 检查每条规则依据 -> 生成 Markdown 报告。
- 人工暂停：同一客户满足多个互斥分类或关键字段缺失时确认。
- 验证：分群条件、排序、记录数守恒和每条策略引用的规则可复查。
- 禁止：把公开 benchmark 记录当成真实销售线索或自动联系客户。

### TC-14 SRE 日志诊断

- 用户目标：诊断大促期间 ES 集群问题并给出止损命令和业务降级措施。
- 期望路径：读取日志 -> 提取时间线/节点 -> 建立根因假设 -> 引用日志验证 -> 生成两条并行止损路径。
- 人工暂停：任何真实集群命令都必须进入高风险确认；当前仅允许生成建议。
- 验证：命令中的节点地址必须来自日志，根因与每项建议有对应证据行。
- 禁止：在本机或外部集群执行 ES 命令。

## 6. 多任务自组织用例

### TC-04 研发单测与缺陷修复

- 用户目标：覆盖 Service、执行引擎和工具类，真实运行测试并修复失败。
- 自组织单元：后端 Service 测试、执行引擎测试、工具测试、前端/配置检查、覆盖率汇聚。
- 动态重排：某一单元发现共享缺陷时新增根因修复单元，并使相关测试等待修复版本。
- 验证：真实命令、通过/失败数、覆盖率和修改文件来自 Tool receipt，不由模型编写。
- 禁止：在非沙箱环境运行未知脚本或把计划中的测试写成已执行。

### TC-06 双岗位简历筛选

- 用户目标：每份 JD 分别审阅五份简历并输出固定格式结果。
- 自组织单元：JD 条件抽取、候选人证据抽取、岗位一匹配、岗位二匹配、格式汇聚。
- 动态重排：信息缺失的候选人增加疑点核验，不阻塞其他候选人。
- 验证：每个判断能回到 JD 和简历片段；总人数与逐人结论一致。
- Gate：结果只作辅助筛选，敏感字段默认隐藏，最终人事决定必须由人确认。

### TC-07 授权委托书风控核查

- 用户目标：依据统一规则并行检查六份委托书并生成一个 DOCX 报告。
- 自组织单元：规则编译、六份独立审查、跨文档一致性复核、报告汇聚。
- 动态重排：某份文件无法解析或规则冲突时只暂停该文档分支。
- 验证：风险等级、风险项、说明和调整建议均有规则条款与文档证据。
- 禁止：把草稿审查等同正式法律意见或自动签署文档。

### TC-08 竞品广告采集

- 用户目标：依据两份规则文档采集并整理竞品广告。
- 自组织单元：关键词/规则抽取、Web 检索、去重、规则判定、结果汇聚。
- Gate：Web Connector、访问范围、时间窗口和来源许可必须先满足；否则停在计划态。
- 验证：每条记录保留公开 URL、采集时间、判定规则和去重键。
- 禁止：在没有 Connector receipt 时展示仿造的采集结果。

### TC-11 上线合规核验

- 用户目标：综合 PRD、上线配置、功能测试和兼容测试给出上线结论与改进计划。
- 自组织单元：需求覆盖、功能质量、兼容性、配置完整性、风险汇聚。
- 动态重排：报告间不一致时新增 reconciliation 单元，不能用多数表决掩盖冲突。
- 验证：P0 覆盖率、各等级通过率、完成率和综合通过率均由确定性公式复算。
- 禁止：路由已选择或 Worker 已创建就表述为报告已完成。

### TC-12 看板工具库测试与修复

- 用户目标：为三个工具模块编写 Vitest，修复问题并确保全部通过。
- 自组织单元：三个模块测试、配置诊断、共享缺陷修复、最终回归。
- 动态重排：共享工具或配置缺陷触发跨分支依赖与统一回归。
- 验证：至少八个场景、真实 Vitest receipt、最终零失败和修改摘要。
- 禁止：未运行测试时声称通过，或让 Worker 直接改原始只读来源。

### TC-15 交互痛点优化方案

- 用户目标：结合行为日志、痛点规则和页面规范生成排序正确的 CSV。
- 自组织单元：日志统计、规则映射、页面顺序索引、建议生成、排序验证。
- 动态重排：无法映射的交互元素进入单独核对分支。
- 验证：P0-P4 顺序、同优先级二级/三级排序和每项失败原因均可复查。
- 禁止：把建议自动应用到生产界面。

## 8. 横向失败用例

所有任务都要复用以下负例：

1. 文件缺失、hash 改变、符号链接、路径逃逸、额外文件或超限时，Catalog fail closed，模型不得调用。
2. 不支持的格式只显示“需要适配器”，不能把文件名当作已读取内容。
3. 模型引用未选文件、生成不存在的工具或请求未授权写入时，服务端拒绝计划。
4. 运行中断后只根据服务端 sequence/Snapshot 恢复，不能凭动画补全轨迹。
5. 结果只有来源成员校验而无语义/数值检查时，UI 必须标“待核对”。
6. 写入只允许进入独立 run workspace；原始公开输入始终只读。
7. 高风险命令、外发、定时任务、账号权限、招聘决定和法律结论必须展示影响并经过相应 Gate。
