# DR-0075：Demo1 以办公交付为主线

日期：2026-10-10。状态：Limited Verified，验证范围以 [Evidence](../evidence/DR-0075-DEMO1-CLARITY-20261010.md) 为准。

## 场景与来源

[用户授权与反例](../sources/USER-FEEDBACK-20261010-demo1-clarity.md)；
[SCENARIO-062](../scenarios/SCENARIO-062-understand-current-office-delivery.md)。
用户需要从原系统理解任务在做什么、产出什么，而不先理解 Run 恢复协议。

## 前台交互影响

- 当前成果优先按真实文件显示已生成数量和文件检查通过数量；没有文件时才显示逻辑简报版本。
- 没有新成果的子 Run 明确区分本次未生成与旧记录保留，不把父版本冒充新交付。
- 业务否决保持在摘要可见，文件检查通过不代表上线批准。
- 生成文件也计入“保留成果”阶段，但不代替证据门通过或整个任务完成。
- 历史轮次标为历史记录，不再叫“当前问题”；第零轮称本次执行，不显示“第 0 轮”。
- 顶部正在预览的文件名只在预览页显示，执行与成果视图不将其冒充当前任务来源。
- 修复续办测试数据，清除父 Run 的轮次结果、分支、预算停止和决策；不改 Runtime。

## 后端事实映射

文件数量及检查来自 `workspace_artifacts[].verifier_status`；否决来自 `business_gate_outcome`；
逻辑成果来自 ArtifactVersion/TaskCommit；当前轮次来自 `current_round`，历史轮次来自选中记录编号。
没有 API、模型 Prompt、来源、预算默认值或权限变更。真实录屏单次任务显式限制 3 轮/6 调用/600 秒，
等待人工或终态即停止观察，不代选、不自动续办。

## 验证与边界

浏览器验证覆盖有文件但无逻辑版本、文件失败、业务否决、续办与原 Demo2。真实单次任务不证明
多轮稳定性、通用办公能力、完整长任务或用户效率。旧模拟录屏保留历史，不再作为当前办公效果证据。
