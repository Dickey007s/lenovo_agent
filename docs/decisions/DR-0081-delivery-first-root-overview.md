## 场景与来源

[用户反馈](../sources/USER-FEEDBACK-20261022-task-overview.md)指出局部去重变化不明显。
根页仍重复成果摘要与完整成果，成果下载在执行信息后，成功终态默认展示整轮说明。
这是用户反馈与开发者走查，不是目标用户研究；nanoMuse 没有新增检索或复制代码。

## 前台交互影响

- 原根页把真实成果放在历史、调度与轮次记录前，不另立产品入口。
- 有文件且全部工作完成时，不再重复渲染交付摘要；完整成果入口在真实文件区。
- 有未完成项时，按整个 Run 的 Branch 列出全部未完成工作，不受当前轮次或前三条限制。
  已完成项按需展开；待处理项提供直接核对入口，仍使用原证据审查与权限。
- 普通成功终态可折叠整轮执行记录。存在未完成 Branch、开放决定或所选轮次缺口时不折叠。
  当前来源覆盖受限、延后要求、缺源也阻止折叠；历史只读、来源变化、查询失败保持独立可见。
- compact 业务条件保留结论、每条名称、实际值和阈值；公式与计算说明按需展开。
  完整成果页保持原细节。文件失败与下一步处理不折叠；代码自测卡保留。
- 桌面发布复核区并列业务结论与文件，手机仍按顺序显示；普通执行范围和重复结语按需查看。
- 任务视图将资料库数量/许可移入原“数据与执行边界”；资料预览和空白任务仍直接显示。
  桌面任务设置与原页签共用一行，错误、设置展开、原入口保持可达。

## 后端事实映射

`workspace_artifacts`、`effect_receipts` 决定文件内容和通过状态；`business_gate_outcome` 决定业务结论。
Branch 状态决定未完成集合，整个集合不截断。轮次、决定请求和输入覆盖共同控制本地折叠。
历史轮次曾有缺口，不等于当前仍待办；切换到有缺口的历史轮次时记录保持展开。
来源状态、错误、版本、控制权限继续来自原 Snapshot、Task 指针与请求归属，不从排版推断。
没有服务端、协议、模型输入、SSE 或权限变更。查看详情、结果和依据不提交控制命令。

## 验证与边界

验收涵盖桌面/390 px、业务否决、文件失败、完整成果入口、键盘展开、全部未完成项与跨轮次待办。
既有 Loop、Swarm、来源核对与整合测试一并回归；具体结果只记录在 Evidence。
本轮不证明模型质量、业务批准、真实下游恢复、数据库恢复或真人理解提升。
能力页整体布局与其他行业长结果面板并未全面改版。
