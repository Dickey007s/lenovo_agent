## 真实问题

此前入职、财务、上线任务已生成检查通过的文件，但模型说明可以给出不同人数、金额、提测率。
真实复跑又暴露：Worker 准入等待消耗 active deadline、首批准入缺少明确 ready IDs、空闲等待时
停止命令没有运行任务来处理、编号的下游步骤被根任务限定误拒、指标阈值被误当实际值。
这些失败不应被漂亮 UI、测试总数或模型调用成功掩盖。

## 决策

1. 入职 CSV 的人数、期间和用途由真实生成记录派生。财务及上线复用现有结构化 Outcome；只有
   passed Effect、有效 Outcome 或明确绑定的 passed 入职 Artifact 才可建立核对上下文。
2. 对明确表达的当前人数、财务合计/条数、候选数、上线比例/配置数做受限数值比较。比较完整
   文本而不是先裁到 500 字；审计摘录仍有限长。PRD 要求、准入门槛等规范值不冒充实测值。
3. 三类新增对账即使数值相同，模型自由说明仍是 supplemental 草稿，不进入正式当前发现；
   冲突是 rejected。无法匹配的措辞是未知，不是通过。此规则不是通用语义验证器。
4. `rounds[].model_input_coverage[]` 记录实际发给模型的安全 payload：file_ref、行/字符/元数据、
   提供数量、已知总量和 bounded。表格仍最多 60 行、文本仍最多 12000 字符；不声称已实现全文续读。
   无正文的空 rows 字段不能把 PDF 文本误算为零行表格。并发 Worker 合并同轮文件记录。
5. 原进展页提供可展开的资料范围，区分文件生成成功与模型说明待复核。Authority 提示同时要求
   对账回执、对应 passed Effect 与绑定的 passed Artifact；没有回执不能从文案推断权威。
6. Worker 初次准入记录服务端 ready IDs，尚不创建执行台账或调用模型。确认后才预留预算并启动
   active 时钟；每波完成/等待冻结时钟；过期或控制命令在途时拒绝新派发。等待分支可暂停态恢复；
   空闲等待时 stop 也能到达终态，保留已采用结果。停止不取消在途 Provider 请求。
7. Worker 返回后的来源校验失败仍记录 called=true/output_used=false。聚合 Anchor 上限与
   96 条 Finding、每条最多 6 个 Anchor 对齐为 576，不引入隐藏六条总引用限制或静默裁剪。
8. 延续并修订 DR-0059：显式编号 `planned` 可绑定唯一根单元或合法下游单元。编号完整性、
   不共用单元、依赖 DAG、来源合并、文件预算与 allowlist 继续校验；不是通用需求理解保证。
9. 对比必须记录实际 topology，而非脚本 case 名。被准入为 fixed_workflow 的请求不能算成蜂群。
   同指令但计划、范围或结果不同的单次运行，不能用耗时比例宣传性能领先。
10. 确认前用已校验 Branch DAG 展示“计划工作包 · 尚未派发”，不创建或伪造 WorkUnit 执行回执。
    手机按依赖层顺序纵向排版，并保留明确前序编号，避免横向与节点内部裁切。

## 边界

保留同一个 Task/Run/Snapshot 框架，没有新增 API path、执行权限或替代 UI。不改变原始资料，
没有分布式 Worker、外部办公动作、通用写入沙箱、语义正确性或目标用户研究。
依赖排序和贡献采用不等于已实现智能体讨论、动态角色学习或通用协商。
下游当前主要读取其批准来源重新分析，尚不能宣称所有下游都消费了前序完整推理结果。
Demo3 接入约定不在本轮范围内。
