## 决策和前台交互影响

沿用当前统一工作台和八模块划分。在中心工作区新增通用“办理事项”，提供五类可填写内容的操作，不引入运行时 Demo ID 或固定情节播放器。左侧资料预览不变，右侧显示服务端事项轨迹。

低风险文本直接处理且可恢复原值；资料摘录保留草稿和来源；协作任务普通确认；测试发件强确认；受限请求停在人工办理说明。L4 显示完整对象和正文，并单列核对要求。修改后重新检查，暂缓保存当前内容，取消无提交。断网显示结果未知并保留原请求重试。

该路径采用固定服务端策略，不调用模型。五种操作是当前明确的测试能力：个人文本副本、逐字摘录、测试任务、测试发件、受限检查。不能把记录下载称为已通过 Verifier 的 Run Workspace Artifact，也不能声称完成真实发件或企业任务创建。

## 后端事实映射

模块 2 接收严格的 `ActionInput`；模块 4 产生固定策略状态和确认要求；模块 8 保存 Snapshot、事件、版本与幂等回执。现有控制器承载动作生命周期，但该路径不使用 Planner、Worker 或模块 6 的外部网关。

`office_action` 为服务端权威。start 接收可选 `action`，普通研究 Run 行为保留；独立 action-controls 接收版本、内容 revision、幂等键及必要核对。普通 Loop controls 拒绝事项 Run。Owner 不符返回 404，版本冲突返回 409，客户端附加风险字段返回 422。修改必须保持操作类型，旧核对不沿用。

回执和 Snapshot 在同一 store commit 中保存，失败时恢复旧内存状态。事项恢复不重放动作；无数据库时重启不保存。未签名 Owner、多实例一致性、真实审批、权限变更和外部去重不在当前保证内。

详细字段见 [API](../API.md)，各 UI 状态见[事实映射](../contracts/UI_SERVER_FACT_MATRIX.md)，规则与案例对应见[开发版手册](../design/DEMO3-DEVELOPMENT-HANDBOOK-20260918.md)。
