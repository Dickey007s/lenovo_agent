## 交互决策

1. 新建任务删除三个常驻案例、范围小字及重复的任务确认块。剩余分工示例折叠。运行预算仍可在设置里查看修改；主进展只显示已用轮次、调用，不展示分母。
2. 首轮按“读取本轮资料、按任务要求分析、核对引用保留结果”呈现实际处理流程。每个已校验计划项仍可展开。流程阶段不是新生成的模型子任务，不代表 Planner 已能细分任意任务。
3. 普通 Finding 的依据页直接显示结论与原文，不显示“旧结果”“会保留/不会做”处置模板，不为它自动创建人工业务决断。业务待决、来源歧义、失败恢复的控制不变。
4. 依据列表只留一个核对入口，直接打开现有有焦点管理的审查对话框。普通文件预览滚动到可见处并聚焦，避免在长列表下悄然打开。
5. `result.follow_ups` 标为“可选的后续建议”，不是原任务欠项。未完成分支、缺源、人工待决继续单独保留。历史建议没有独立理由和逐项引用时明确缺少，不推断或编造。
6. 无人工项时不渲染空人工栏；业务否决和未完成项保留。任务内处理记录在滚动时保持可切换，两条记录在手机上并排显示。
7. 主进展的路线区改成简短协作安排；详细准入与调用事实仍可查看。协作窗口与任务页复用同一 Agent 分行视图，展示身份、任务、依赖、状态、可展开的来源和结果。

## 服务端与权限

续办的私有 `round.question` 包含 Planner 所需的原目标与上一请求背景。公开 `round.question` 改为使用同一 Snapshot 的业务 `instruction`，仅针对 `parent_run_id` 存在且 `continuation_reason=执行后续建议`；`steer_instruction` 单独保留。旧内存/持久记录同样在公开投影时处理，不改写私有历史。浏览器也按相同身份条件显示业务指令，兼容尚未重启的旧服务。

没有新增 path 或字段。模型上下文、任务身份、版本化确认、幂等、工作包调度、预算、权限与执行行为均不变。Demo2 仍按 `automatic_readonly` 执行；Demo1 既有协作授权不被绕过。

Agent 行来自实际 WorkUnit。尚未派发是计划岗位，不声称已启动；贡献采用需同 attempt、同 Branch 和当前 Contribution。依赖阶段不等于并发波次。没有台账的历史记录仍显示计划，不编造 Agent 执行。
