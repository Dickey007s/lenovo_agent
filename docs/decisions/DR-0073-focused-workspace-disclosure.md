## 场景与来源

用户在询问 nanoMuse 借鉴是否落地后要求继续实现原系统的信息分层。
沿用[固定版本审查](../reports/restart-review-20261007/README.md#nanomuse-的设计启发)的稳定入口、渐进披露与任务优先原则。
不复制其源码或素材；没有竞品实测或用户收益证明。

## 前台交互影响

1. 原 `/` 的过程记录默认收起，顶栏显式打开并移入焦点；关闭或 Escape 后焦点回到入口，打开后保留调整大小。
2. 目录在浏览态默认展开，任务/事项态默认收起；显式切换保留搜索、目录状态与当前文件，新建任务重置显示偏好。
3. 已提交研究任务顶部保留目标和状态；原输入、输出约定及预算进入“任务要求与运行设置”，默认收起。新建恢复空白输入。
4. 问题、业务否决、成果、历史只读与错误仍保留在既有主区，不随日志隐藏。原能力页和事项确认语义不替换。
5. 主区保留最近一次数字/叙事拒绝以及失败/成果恢复回执，来自当前 Run 的有序事件；标为执行记录，不将历史拒绝推断为当前任务未解决。手机顶栏自然换行，文字按钮不挤入图标宽度。

## 后端事实映射

仅改前端。目标与状态取 `run.instruction/run.status`；目录取 Workspace；过程和重要回执取现有活动投影。失败通知额外要求当前 `run.status=failed`。
开关都是本地状态，不发控制 POST、不调用模型、不停止或恢复任务。关闭过程记录不关闭 SSE。
Task/Run/Snapshot、权限、预算、幂等、来源版本和 Worker 决定合同不变。
