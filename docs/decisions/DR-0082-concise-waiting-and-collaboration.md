## 场景与来源

[用户原话](../sources/USER-FEEDBACK-20261022-waiting-copy.md)要求继续精简等待页和协作图。
已有移动截图中，同一缺口在恢复说明、分支卡、四阶段流程与底部状态重复出现。
这是 Stakeholder 反馈与开发走查，不证明目标用户理解或效率。

## 前台交互影响

- compact 等待区合并恢复说明和待办标题，每条保留问题、候选数量或重试性质、影响及原动作。
- 四列箭头流程改为问题与操作两列；手机上下排列。资料、原始原因、引用数进入逐项详情，
  并没有把 Branch 与 Gap 的 ID 关联改成从文案猜测。
- 已通过、尚未通过、旧任务终态仍用不同话术和动作；已通过文件仍先展示，说明仍需复核。
- 根页已有整个 Run 的未完成清单时，当前轮次重复分支详情可折叠。所有未完成项与操作仍在清单，
  包括其他轮次。没有清单时，未完成分支仍展开。此条件替代 DR-0074 对重复分支区一律展开的要求。
- 清单的处理按钮移到对应行，不再另列同名按钮组；恢复原理和重复暂停状态按需查看。
- 协作图保留工作标题、状态、资料数与实际依赖；独立项不再额外列“根”。
  “就绪，待你确认”“分歧待复核”替代混合术语；业务任务标题保持原值。
- 等待前置工作的影响合并为一条，但列出全部受影响名称。缺口标题保留，长原因可展开。
  不再把不同来源的影响条目数标成待确认数量；人工决定数量只来自真实待决集合。
- 协作批准范围、准入时预算、单进程/每批上限和不执行外部动作仍直接可见。
  执行回执保留调用、返回、采用的区别。没有完整待决项的歧义 Worker 仍只查看回执。

## 后端事实映射

waiting 卡片沿用 Branch、Gap、EvidenceResolution、DecisionRequest 的绑定；引用资料仍用安全标签。
Artifact / EffectReceipt 决定成果检查状态；终态仍不能原地 resume。
协作图沿用 WorkUnit.depends_on、Branch 状态和 ready_branch_ids；贡献采用由 gate_status 决定。
合并影响文字不合并后台工作包、不改变调度或权限。所有查看/展开不发控制 POST、不关闭 SSE。
确认、重试、历史只读、来源变更、错误以及版本/幂等规则不改。本轮没有服务端或公开协议修改。

要求桌面/390 px 检查、键盘展开、零新增命令、完整待办、真实依赖、歧义确认与终态续办回归。
结果以 Evidence 为准。受控 Snapshot 与截图不证明真实模型质量、业务批准、下游人工恢复闭环或真人体验收益。
