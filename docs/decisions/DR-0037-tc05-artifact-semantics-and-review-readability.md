# DR-0037：TC-05 成果语义与问题审查可读性

- 状态：Accepted；本地确定性门 `Limited Verified`，PR 门待绑定
- 日期：2026-08-28
- Owner：Office Agent 项目组
- Source：`USER-FEEDBACK-20260828-TC05-ARTIFACT-MEANING-AND-REVIEW-READABILITY`

## 场景与问题

财务人员要求 Agent 核对 2025 上半年、2025 下半年和 2026 三期往来资料。旧成果区只显示
`未付统计.csv`、`未收统计.csv`、记录数、来源数与检查数。用户因此无法在下载前判断：两个
CSV 各覆盖哪个期间，31 与 2 是记录数还是期间数，以及哪个成果真正使用了三期输入。

源码审计确认：两个 CSV 都只从 2026 工作簿取数；只有跨期说明使用三期借方未收余额做
同科目、同客商比较。旧 Artifact 却让三个成果都绑定三份来源和跨期检查，使“任务上下文”
看起来像“文件内容来源”。同一轮反馈还指出问题审查页的正文、事实卡、影响、证据摘录和
安全预览字号过小。

## 决定

1. `AgentControlLoopWorkspaceArtifact` 增加 `covered_period`、`statistic_basis`、`purpose`
   和可选 `record_count`。这些字段由服务端确定性适配器产生，浏览器不从文件名或摘要猜测。
2. `source_file_refs` 对每个 Run Workspace Artifact 表示其**内容来源**。TC-05 的两个 CSV
   只绑定 2026 工作簿；跨期说明绑定三个期间。整项任务使用过的三份资料继续由
   `EffectReceipt.source_file_refs` 表示，不能冒充每个文件的内容覆盖。
3. TC-05 的显示标题改为“2026 期末未付明细”“2026 期末未收明细”“三期僵尸账款核对说明”。
   下载文件名暂不改变，避免破坏既有脚本和测试对 `未付统计.csv`、`未收统计.csv`、
   `跨期核对说明.md` 的兼容。
4. 2026 CSV 各自只保留本期来源、逐行复算与排序检查；三期来源完整性和跨期僵尸比较只归
   跨期说明。31 与 2 通过 `record_count` 明确显示为“条记录”。
5. 问题审查页整体提高信息字号和行高：主要正文与证据至少增加 2 px，辅助元数据至少增加
   1 px。表格仍在自己的预览区域横向滚动；页面和审查页本身不得产生横向溢出。

## 前台与后端事实

| 用户看到什么 | 服务端事实 | 隐藏或禁止推断 |
| --- | --- | --- |
| 涵盖期间、统计口径、用途 | Artifact 的三个同名语义字段 | 不从 `source_file_refs.length` 推断期间 |
| 31 条记录、2 条记录 | `record_count` 与实际 CSV 数据行确定性一致 | 不把记录数解释成期间数 |
| 1 份内容来源或 3 份内容来源 | Artifact `source_file_refs` | 不把 EffectReceipt 的任务上下文冒充内容来源 |
| 逐项检查 | 当前 Artifact 自己的 `checks[]` | 不把跨期检查复制到只含 2026 行的 CSV |
| 放大的事实、影响、摘录与预览 | 同一 Finding/Anchor/Preview 服务端事实 | 字号改变不增加新结论，也不证明语义正确 |

## 交互影响

用户不必先下载三个文件再反推它们的关系；在成果区即可回答“哪个期间、怎么算、拿来做什么”。
审查页则把真实证据保留在同一位置，只提高可读性而不增加解释密度。该变化减少的是前台语义
歧义，不改变 Agent Control Loop、预算、Evidence Gate、下载边界或原文件只读约束。

## 验证与边界

后端单测必须锁定 31/2 数据行、三个显示标题、期间/用途、精确来源和检查归属；浏览器测试
必须锁定三张语义卡、computed font-size、桌面和 390 px 页面级无溢出。自动化与截图只能
证明事实投影和布局，不证明真实财务人员理解改善。`Finance-018` 仍是一个固定 FORTE 适配器，
不是通用财务 Verifier，也不定义生产环境的僵尸账款政策。
