# USER-FEEDBACK-20260826-22：分层文件目录与可核对的问题审查页

## 原始触发

Stakeholder 在当前 Codex 任务中提出两项明确反馈：

> 1. 我说了左边的工作区要做成文件夹的形式，能有层次感的查找文件，展示文件。
>
> 2. 运行时，找到的缺失啊什么的问题，用户需要能在这个页面中快速的点开查看具体是什么样的，比如说 agent 给的建议啊什么的，能有一个入口让用户直接点击，点击后是弹出一个新页面来展示，用类似展示 git 提交记录的方式展示哪里有问题有什么问题，让用户看得更清楚。现在的问题就是用户看到你这里说有什么问题，但是没法很方便的查看对应的内容是不是有这个问题。

## 支持的判断

- 左侧资料库不能继续把 96 份文件平铺为一张长列表；必须按服务端安全
  `display_path` 投影为可展开、可折叠、可搜索的目录树，并保留嵌套子目录。
- Evidence Gap、Branch 缺口、Finding 和下一步建议必须提供就地“查看问题/打开审查页”
  入口，不能只显示摘要或计数。
- 审查页应把 Agent 描述、服务端记录、人工核对位置和真实文件预览组织在同一视图，
  让用户直接判断问题是否成立。
- “类似 Git 提交记录”支持使用可追溯时间线和关联文件列表，不授权伪造行级 Diff、
  文件修改或语义验证结果。

## 局限

- 这是单一 Stakeholder 的形成性反馈，不是目标用户样本、可用性实验或效率测量。
- 反馈支持交互问题和方向，不证明新的目录树或审查页一定更易懂、更可信或更高效。
- 当前 `follow_ups` 是字符串列表，没有逐条来源绑定；审查页只能诚实展示本轮结果上下文，
  不能把上下文文件冒充为建议的直接证据。
- 当前安全预览是有界提取，不提供文档原生排版、页内定位或字段级高亮。
