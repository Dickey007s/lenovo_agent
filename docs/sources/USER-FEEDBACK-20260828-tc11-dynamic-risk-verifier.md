# 用户反馈：TC-11 风险总数与 PRD 等级必须真正动态

- Source ID：`USER-FEEDBACK-20260828-TC11-DYNAMIC-RISK-VERIFIER`
- 类型：Stakeholder 独立源码验收与可证伪性复核
- 日期：2026-08-28，Asia/Shanghai
- 关联：`DR-0043`、`SCENARIO-029`、TC-11

## 发现

独立验收确认第一版来源推导仍有三个残余固定样本事实：生产 Verifier 要求风险总数必须等于 8；DOCX、Artifact 摘要和复核引导写死“8 项风险”“5 项未提测”；PRD 原因规则虽然读取等级单元格，却仍按原因名称集合映射主要或次要。

这会同时制造 false red 与 false green：合法修复 F02 后 builder 会得到 7 项风险，但 Effect 会被固定总数错误判红；若 PRD 把“功能缺陷”的基础等级调整为次要，旧实现仍会静默判为主要。

## 要求

- Verifier 必须从 18 行记录动态复算各风险等级、风险总数、记录唯一性和唯一最高等级，不检查固定 8。
- DOCX、Artifact 摘要、复核引导和前台投影使用同一服务端动态数量。
- PRD 原因类型的基础等级必须从等级单元格解析；未知或同时包含主要/次要时 fail closed。
- F02 合法修复后完整 `ScenarioEffectEngine` 仍应通过，两份成果和台账变为 7 项风险，旧“8 项”不得残留。
- Evidence 必须记录真实 live Run 的非敏感 `X-User-Id`，使他人可以按 Owner 边界复读。

## 边界

这是独立源码验收，不是目标用户研究。F02 与 PRD 等级变异只证明固定 `pm-014` 适配器的规则和数量能随批准来源变化，不证明任意发布资料、真实上线、配置写入或通用规则引擎。
