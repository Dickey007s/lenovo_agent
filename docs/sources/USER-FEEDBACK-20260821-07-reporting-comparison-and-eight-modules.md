## 支持的判断

- 汇报材料必须把技术差异翻译成用户流程差异，而不是只列模型、框架或功能名称。
- 每项方案判断必须保留目标场景、来源类别、精确引用/日期、前台影响、后端事实映射和验证边界。
- OpenClaw、Codex、Claude Code 以及 LangGraph 应作为官方材料参照；官方材料只能支持能力与定位判断，不能被表述为竞品实测、竞品缺陷或用户效果证据。
- 八个常驻 Runtime 模块应作为后续拆解与汇报主线，但新增实现事实在前后端完成并有证据之前只能标记为 `Draft`/待验证。
- Sol/Luna 是本轮协作编排偏好，不是 Office Agent 的用户可见模型选择、业务效果或生产运行结论。
