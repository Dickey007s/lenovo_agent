# USER-FEEDBACK-20260820-04 · 处理路径与等待真实性

- 类型：Stakeholder 浏览器试用反馈
- 时间：2026-08-20，Asia/Shanghai
- 原文：“来你把后台的log提取一下，怎么还是我一按就秒执行了，调用大模型不需要时间的吗，我感觉极不真实”
- 触发场景：本地 `http://localhost:3000/` 中操作 Demo 2 路由选择，并在报价工作台请求综合折后比例核算。

## 支持的判断

1. 普通用户无法从现有界面判断一次 Agent 反馈来自确定性公式、策略规则还是语言模型。
2. “确认执行方式”等文案会把只写入路由选择的毫秒级操作误解成已经启动 Agent 执行。
3. 真实模型等待应显示当前调用阶段，并在完成后保留模型名与实际耗时；确定性快路径应明确标明未调用模型。

## 当时运行事实

- API access log 记录了 Demo 2 route POST 与报价 Conversation SSE 请求，但旧日志没有处理路径、模型调用或耗时字段。
- `GET /v1/demo2/cockpit` 返回 `execution_status=not_started`，回执明确只记录路由，不创建协作单元或外部动作。
- 报价 Thread 中用户消息创建于 `2026-08-20T09:15:10.825147Z`，确定性回答消息创建于 `2026-08-20T09:15:10.828728Z`；该路径由服务端 Decimal 公式生成，不调用 LLM。消息创建时间不等于完整 SSE 交付耗时。

## 局限

这是单一 Stakeholder 的试用反馈，不是目标用户研究。毫秒级规则处理本身不是缺陷；缺陷是处理来源、真实执行边界与耗时不可见。该反馈不证明模型质量、供应商 SLA 或人为增加等待会改善体验。
