# 用户反馈：TC-11 必须从来源规则推导上线结论

## 来源

- Source ID：`USER-FEEDBACK-20260828-TC11-DERIVED-RELEASE-GATES`
- 类型：Stakeholder 场景验收、历史实现审计与前台可理解性要求
- 日期：2026-08-28，Asia/Shanghai
- 关联：`DR-0043`、`SCENARIO-029`、TC-11

## 用户要求

用户以普通办公指令“综合 PRD、上线配置、功能测试和兼容测试，给出上线结论与改进计划。”触发任务。系统只能读取 FORTE `pm-014/input` 的 PRD、上线配置、功能测试和兼容测试四份公开资料，必须逐行校验并从 PRD 规则推导风险和上线 Gate；不得把固定功能名称、固定百分比或“不得上线”文案写成判定依据。

历史实现虽然在固定样本上得到严重 4、主要 2、次要 2，但等级集合由功能名称硬编码，检查又只验证同一组硬编码名称，因此属于可自证为绿的假门。用户要求用来源行变异证伪：F17 异常环境数变化、F05 原因类型变化、F02 问题消失时，风险等级必须随输入变化。

前台还必须区分两类事实：确定性检查通过只表示来源、公式和文件结构经复核；四条业务 Gate 全部失败才决定“不得上线”。业务失败不能被绿色检查盖过，也不能把用例通过率辅助指标冒充正式上线条件。

## 影响与边界

这条反馈支持建立逐功能风险台账、显式公式 Gate、双状态前台、可下载 DOCX/CSV 和失败不伪绿的验证链。它是单一 Stakeholder 反馈，不是用户研究，也不证明固定 `pm-014` 适配器可以处理任意发布资料、执行真实上线、修改配置或提高用户决策质量。
