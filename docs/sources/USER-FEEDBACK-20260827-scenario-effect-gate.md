# 用户反馈：场景效果必须真实验证，而不是只调预算

## 来源

- Source ID：`USER-FEEDBACK-20260827-SCENARIO-EFFECT-GATE`
- 类型：Stakeholder 研发方向与验收要求
- 日期：2026-08-27，Asia/Shanghai
- 关联：`DR-0035`、`SCENARIO-021`

## 用户原始要求摘要

1. 取消固定三轮造成的常见停止，把完整任务的轮次、每轮文件、模型调用和 active deadline 提高到可用范围。
2. 不再以“模型返回了文本”“Run completed”或“有引用”替代任务效果；TC-01 至 TC-15 必须登记独立指令、输入、预期成果、确定性验证、前台效果、服务端事实和禁止副作用。
3. TC-01、TC-05、TC-10、TC-13、TC-14、TC-15 必须运行真实 `deepseek-v4-pro`，生成真实运行工作区文件并通过确定性 Verifier；失败后继续修复。
4. 代码和多文档场景先跑红灯再补实现；外部 SQL、Web、定时或真实副作用没有授权时保留 `blocked_external_boundary`，不得伪造。
5. 产品继续保持 Workspace-first，不增加 Scenario 选择器，不把 `task.md`、rubric 或 solution 暴露给用户或模型。
6. 每次运行保留 `state -> action -> observation -> cost -> result`，模型质量、成果正确性和用户体验分别举证。

## 支持的判断

- 预算必须是独立安全边界，不应再由三轮成为普通办公任务的常见停止原因。
- 场景效果必须落到可下载文件和确定性检查；引用只证明来源位置，不能证明数值、排序、规则或测试正确。
- 已完成的确定性成果不应被随后未采用的 Analyst 文案抹掉。
- 外部依赖缺失时，正确结果是结构化阻断和零副作用，而不是模拟成功。

## 不能支持的判断

- 这是单一 Stakeholder 的方向与授权，不是目标用户研究。
- 不能由自动化或截图推导用户理解、效率、信任或业务价值改善。
- 不能由本地固定适配器推导任意办公任务、生产安全沙箱、真实 Connector 或外部动作已经实现。
- 不能由竞品资料缺少相同字段推导竞品“做不到”。
