# 用户反馈：TC-07 文档卡必须跟随内容区宽度

## 来源

- Source ID：`USER-FEEDBACK-20260829-TC07-CONTAINER-READABILITY`
- 类型：Stakeholder 合并后页面截图复核
- 日期：2026-08-29，Asia/Shanghai
- 关联：`DR-0044`、`SCENARIO-030`、TC-07

## 反馈事实

PR #59 合并后的 1440 px 三栏页面中，中央成果区实际只有约 570 px，但授权委托书列表仍依据浏览器 viewport 采用两列。每张卡因此过窄，`委托书1.docx`、`委托书2.docx` 被拆成四到五行，展开后的来源事实与规则判断也被压成窄列。服务端的法务结论和 126 条台账没有变化，问题只发生在前台布局投影。

## 交互要求

文档列表必须按自身内容宽度决定一列或两列，而不是把 1440 px 浏览器误当成中央面板宽度。常见桌面状态下，每张卡至少保持可读宽度，文件名最多两行；展开后的原文位置、摘录、来源事实、规则判断和处置条件也应按内容宽度退成一列。390 px 页面继续保持单列且不得横向滚动。

E2E 除截图外还要读取真实几何和 computed style：1440 px 状态下列表只能是一列，或每张卡至少 320 px；文件名不超过两行；展开事实只能是一列，或每格至少 300 px；桌面、390 px 页面和法务结果容器均无横向溢出。

## 边界

这条反馈支持修复 TC-07 的响应式可读性，不改变 `legal_review_outcome`、`business_gate_outcome`、Artifact、EffectReceipt 或任何后端法务判断。单一 Stakeholder 截图复核和浏览器自动化不能证明目标用户理解、法律判断质量或生产浏览器覆盖。
