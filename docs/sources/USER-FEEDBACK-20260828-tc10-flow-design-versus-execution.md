- Source ID：`USER-FEEDBACK-20260828-TC10-DESIGN-VERSUS-EXECUTION`
- 类型：Stakeholder 场景验收与前台语义要求
- 日期：2026-08-28，Asia/Shanghai
- 关联：`DR-0039`、`SCENARIO-025`、TC-10

## 用户要求

用户要求用原指令真实运行 `deepseek-v4-pro`，下载并打开 DOCX，再核对 13 项合规流程 Gate。前台必须明确区分：生成流程设计文档、文档中描述的未来动作、以及本次 Run 实际发生的动作。未拨号、未写 CRM、未发短信不能只藏在技术详情里；用户还应直接看懂采用依据、六类终态和人工复核原因。

## 触发负例

修复前 Run `harness:e9741612bba44444abc15c82d6246dc8` 实际调用 Planner/Analyst 并生成可打开 DOCX，13/13 检查通过，但成果卡主要突出“文件已生成”和检查数量。未执行边界只出现在摘要、折叠检查或区域页脚；下载文档也以连续边列表为主，缺少“回答什么、采用什么、为什么复核”的首部说明。

## 支持的判断

- 设计成果和执行回执必须在首屏分层显示，不能靠用户从 `external_action=none` 推断。
- 流程节点中的动作名称不能冒充本次 Run 已执行的动作。
- 固定适配器拥有的成果类型、适用范围、采用依据、关键输出、人工复核原因和实际执行边界应成为服务端事实。

## 不能支持的判断

- 单一 Stakeholder 反馈不是目标用户研究，不能证明新布局提高理解、效率、信任或业务效果。
- 13 项固定检查只证明当前 FORTE `Operations-008` 输入与固定流程合同，不证明通用外呼引擎、生产合规审批或外部系统接入。
- “未执行”是本次 Run 的事实，不表示未来生产流程不需要拨号、CRM、短信或其他受控 Connector。
