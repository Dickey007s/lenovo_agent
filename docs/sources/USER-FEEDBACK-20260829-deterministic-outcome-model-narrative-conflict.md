# Stakeholder 反馈：确定性成果与模型说明不能同时成为“当前真相”

- Source ID：`USER-FEEDBACK-20260829-DETERMINISTIC-OUTCOME-NARRATIVE-CONFLICT`
- 日期：2026-08-29
- 类型：真实浏览器复读后的产品反馈与失败样本
- 关联：`DR-0052`、`SCENARIO-037`

## 触发事实

历史 TC-15 Run `harness:731c429f82a941438b838fa8982699fd` 中，服务端确定性成果已经从完整工作簿复算出 `212/212` 行、`87` 个组合和 `25/40/14/6/2` 的优先级分布；同一 Run 的 Analyst 说明却声称只看到前 60 行、仍需统计全部 212 行，并把一项按来源矩阵得到的 P0 改写为 P1。旧 Runtime 仍记录 `output_used=true`、Run `completed`，造成两个互相矛盾的“当前结论”。

## 用户要求

1. 确定性效果先形成，并把紧凑、权威的服务端复算事实提供给 Analyst；bounded Preview 只作原文引用，不再冒充完整计算输入。
2. Analyst 返回后必须与当前确定性成果对账，再决定 `output_used`。覆盖范围、数量、优先级、未批准方案或重复要求已经完成的计算发生冲突时，模型说明不得进入当前结果、发现、建议、Brief 或 Commit。
3. 已通过的 Artifact 与 EffectReceipt 不因模型说明被拒而失效。前台只保留一个当前结论，并将冲突回执折叠在执行轨迹中，不要求用户额外处理。
4. 前台只有在 `narrative_reconciliation.authority=deterministic_outcome` 且存在已通过成果/回执时，才显示“以服务端确定性成果为准”。只有失败或受限回执时不得冒充权威结论。
5. 面向普通用户使用“服务端复算结果”“确定性成果”“模型说明未采用”，英文 `outcome` 只保留在协议字段或内部文档中。

## 支持判断

该反馈支持新增通用 `narrative_reconciliation` 协议、模型叙事采用门、单一当前结论和前台渐进披露。它也补充了“模型已返回”和“内容已采用”必须分离的真实失败样本。

## 局限

这是单一 Stakeholder 对一条真实 Run 的审阅，不是目标用户研究。对账规则只核对模型叙事与当前结构化确定性事实的一致性，不证明叙事全面、建议有效、排序具有外部效度或用户体验已经改善。
