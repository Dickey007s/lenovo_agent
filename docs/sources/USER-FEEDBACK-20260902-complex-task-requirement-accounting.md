# Stakeholder 反馈：复杂任务分支不能丢项，分析失败必须可解释

- 日期：2026-09-02，Asia/Shanghai
- 类型：浏览器试用反馈与修复授权
- 适用决策：`DR-0059`

## 直接反馈

Stakeholder 在真实复杂任务中明确提出：

1. 输入列出六个业务分支时，页面只看到五个，无法判断是漏项、资料缺失还是预算延后；
2. “Planner 没有在公开资料中找到对应文件”缺少可核对的解释，且与资料库中实际可见文件不一致时尤其令人困惑；
3. 分析模型返回严格 JSON 失败后，用户无法判断模型是否调用、失败是否阻塞整个任务，以及成功后页面应显示什么；
4. 要求修复这些问题并自行测试复杂任务效果；本次修改不进入 PPT。

## 转化为可验收要求

- 明确编号的要求必须逐项记账，不能把“没有进入本轮”静默等同于“没有这个分支”；
- 本轮执行、已知来源但延后、当前索引没有来源三种状态必须分开；
- 资料库安全元数据需要给 Planner 足够的业务检索线索，但内部提示不得进入公共 Workspace/API；
- Analyst 的截断、非 JSON、Schema 错误、超时和来源定位失败必须有不同的服务端记录；
- 允许一次受控修复；能通过的部分保留，完全不可采用时进入分支级恢复，不把失败文本冒充结果；
- 没有 `ready_branch_ids` 时，不得显示会派发空 Worker 波次的按钮；延后项必须有真实的单分支继续入口。

## 证据边界

这是单一 Stakeholder 的问题报告和研发授权，不是目标用户研究，也不证明修复后理解、效率、
信任或业务质量提升。真实 Provider 运行只能证明列出的协议状态和被测输出，不能证明所有复杂
任务都会正确拆分或得出正确业务结论。
