# USER-FEEDBACK-20260820-05 · Demo 身份与调用轨迹可见性

- 类型：Stakeholder 产品反馈
- 时间：2026-08-20，Asia/Shanghai
- 原文： “前端要看见 Demo1/2/3 且知道调用了什么”
- 触发场景：连续查看 Office Agent 的 Demo 1、Demo 2 和 Demo 3 页面，并尝试理解 Agent 当前正在做什么、实际调用了哪些服务或工具。

## 支持的判断

1. 前台需要明确告诉用户当前处于 Demo 1、Demo 2 还是 Demo 3，以及该 Demo 的业务目标。
2. 用户需要区分“真实调用了什么”“明确没有调用什么”和“尚未执行什么”，不能只从按钮、颜色、动画或技术事件名称推断。
3. 调用轨迹应使用业务标签和服务端摘要；Prompt、思维链、原始 payload、密钥、内部 ID 和无决策价值的底层日志不应进入普通业务 UI。

## 设计含义

- Demo 身份导航应成为首屏业务定位的一部分，而不是隐藏在内部路由或开发者日志中。
- Demo 1 需要能说明任务阶段、是否调用模型以及当前阶段是否由确定性服务推进。
- Demo 2 需要能说明路由选择是否只记录本轮方式、是否启动真实协作或外部动作。
- Demo 3 需要能说明治理 Run、Permit、Gateway 和 Simulator 的业务状态，同时明确真实外部系统没有被写入。
- 任一调用事实缺失、结果未知或跨进程无法对账时，前台应显示“待核对”，不能补造“已调用”或“已完成”。

## 局限

这是单一 Stakeholder 反馈，不是目标用户研究，也不证明增加 Demo 导航或调用轨迹会改善理解、效率或信任。当前工程事实、接口字段、事件时序、截图和用户测试均待 DR-0013 单独回填；该反馈不授权展示 Prompt、思维链、密钥或原始审计 payload。
