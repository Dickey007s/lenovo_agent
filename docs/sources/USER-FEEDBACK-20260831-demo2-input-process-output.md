## 支持的设计判断

1. Demo 2 必须有一条可直接粘贴的普通办公指令、明确的真实输入文件清单、服务端形成的
   工作包依赖、用户可观察的等待与失败，以及可审查的当前输出。
2. 当前纵切选择“跨职能风险与待办简报”：分别核对产品上线、搜索 Agent 运行和用户
   交互三条独立工作线，再收敛优先级和下一步。三条工作线必须分开表述，不能把不同
   项目的数字混成同一个产品结论。
3. 多 Worker 不是用户输入“多 Agent”后的直接结果。只有 validated plan、跨职能来源、
   真实独立分支、只读边界和剩余预算同时满足，服务端才建议受限 Worker，并在用户确认
   前保持零 Worker 调用。
4. 当前 Worker 路径的交付是 append-only 逻辑 `ArtifactVersion`，不是 DOCX/CSV 下载物；
   前台和汇报必须直接说明这一点。真实下载文件属于后续 Artifact renderer/Verifier
   纵切，不能提前画成已实现。
