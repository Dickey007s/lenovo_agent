## 支持的判断

1. 模型不应负责选择服务端内部副作用枚举；模型只表达工作意图，服务端把意图编译成允许的操作语义并继续做确定性校验。
2. 普通业务 UI 不应展示 `artifact.write`、`run_workspace_write` 等内部契约错误；应展示可恢复的业务语言，内部原值只留在服务端日志和测试中。
3. 模型调用回执必须区分“未调用”“已调用且采用”“已调用但校验未通过”，不能用“未采用”让用户猜测是否真的调用了模型。
4. 已知失败后的“重新规划”是新命令，应使用新的幂等键；只有结果未知的重试才复用原键。
