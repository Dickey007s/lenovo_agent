# SCENARIO-069：知道为何等待以及谁依赖谁

- 状态：Limited Verified，仅限本轮前端回归和截图，见 Evidence。
- 用户：复核办公任务和协作成果的业务使用者。
- 来源：USER-FEEDBACK-20261022-WAITING-COPY；单一 Stakeholder，不是用户研究。
- 触发：一项引用有两个候选位置，另一项仅需重试；或一个协作分析尚未采用，阻塞后续工作。
- 痛点：重复说明、技术词和四列流程挤占操作区，移动端需要长距离滚动。
- 目标：先看到问题和操作，再按需查看资料与记录，不丢失待办。
- 完成条件：全部未完成项可见；两种动作可区分；依赖关系与确认预算保留；查看不提交命令。

## 正常路径

1. 在原任务页看到已有成果、全部未完成工作及对应行操作。
2. 等待区只展示一次待处理总览；每项显示位置选择或重试性质。
3. 按需展开相关资料，关闭后仍可直接操作；打开核对页不会默认选择候选。
4. 协作页先看真实依赖图；侧栏列出当前待办与被影响的下游名称。
5. 只有原显式确认按钮才提交下一批执行；展开回执只读取调用和采用事实。

## 异常路径

- 尚未通过的文件不得说成果可用；终态只打开新任务续办，不对旧任务 resume。
- 其他轮次的未完成项仍在全 Run 清单，不被当前轮次折叠吞掉。
- 输入覆盖受限、来源变化、错误、业务否决和历史只读沿用原显式展示。
- Worker 歧义没有完整待决项：只打开执行回执，不创建候选、不承诺重试解决。
- 查看和展开过程不得发 POST；确认后的网络失败/409 继续走原错误处理。
