# SCENARIO-074：看懂办公任务并在原任务内继续

- 目标用户：需要核对表格、整理文档的普通办公人员。
- 触发：看完初步结果，希望执行一条后续建议。
- 痛点：原先另建任务丢失目标；技术文件与后台过程难以理解。
- 目标：看清输入、处理安排、交付物，在同一任务内保留并切换处理记录。
- 完成条件：服务端 task_id 不变；后续记录绑定原 run_id；历史字节投影不变；页面有可切换的阶段，首轮说明与实际来源一致。
- 来源：USER-FEEDBACK-20261024-TASK-BRANCHES；单一利益相关方反馈，不代表研究样本。
- 生命周期：Limited Verified，见 DR-0087 与对应 Evidence。

## 正常路径

1. 选择“整理 Word 招聘要求”，先看到文档名称和必备/加分条件检查表目标。
2. 编辑要求并启动。Agent 真实规划后展示选择的资料、处理安排及已送入分析记录。
3. 查看带原文引用的结果；未说明字段保持未说明，不自动补齐。
4. 确认后续建议，同 Task 新增处理段，带原目标背景重新核对来源。
5. 切换“初始处理”回看旧结果，再回当前分支；不重复模型调用。

## 异常路径

- 尚在执行：不另建任务绕过，先完成或停止当前处理。
- 来源不足或不能定位：保留可用结果，展示待办，不推断批准。
- 需要协作：遵循 manual 授权，不因“后续建议”自动启动 Worker。
- 服务端受理但回执丢失：同页原 key/payload 重试，不得创建第二个后续段。
- 当前指针过期、他人任务、参数冲突：拒绝或刷新，不覆盖历史。
- 规划尚未返回：显示准备中，不伪造模型思考或已读材料。

前台：统一工作台的任务/依据/成果不变；任务内阶段导航、首轮说明；完整记录保留。
后端：原 continue 路由、Task pointer CAS、Owner、幂等、append-only Run；新增 purpose 与只读 Task 描述字段。
边界：顺序续办不是并行树；原文定位不是语义证明；示例仅提供页面分析，不宣称 Word/Excel 文件写入。
