# SCENARIO-034：从公开问卷与规则推导可复核画像清洗和策略草案

## 用户与触发

- 用户：希望先看清样本清洗、分类依据和异常，再由销售负责人补充策略的业务人员。
- 触发：输入“清洗问卷、完成客户画像分类，并生成差异化销售策略 Markdown 报告。”
- 痛点：旧实现固定样本答案与销售话术，来源变化后可能假绿，也会把公开 benchmark 样本误写成真实客户洞察。

## 主路径

1. Planner 在整库冻结索引中自主选择证据；固定 TC-13 效果门另行冻结一份批准问卷与一份批准规则的原始字节。
2. 服务端校验逻辑 ID、文件名、展示路径、allowlist、声明大小与 file ref；CSV 与 Markdown 未通过结构合同就停止。
3. 服务端从规则行推导中文数字、缺失默认、三类阈值、唯一标签优先级、排除和报告结构。
4. 每个原始样本记录清洗转换、全部画像命中、优先级裁决、最终标签或排除原因；精确重复记录保留到台账，并指向首个样本。
5. Runtime 在隔离 Run Workspace 生成 Markdown 与 CSV；Verifier 重读批准来源，并重新解析两份最终 bytes。
6. 前台先说明这不是客户研究或 CRM 执行，再分开显示确定性检查、清洗事实、策略草案待复核和外部动作未发生；用户可展开样本和来源规则。

## 当前固定输入结论

- 当前批准版本动态解析出 15 条来源规则。
- 11 个原始行中有 10 个唯一业务载荷、1 个精确重复；8 个分类、2 个无法归类，合计排除 3 个。
- 技术型、安全型、敏捷型分别为 3、3、2。
- canonical 没有多标签样本，因此优先级 witness 为 0；优先级只在可证伪变体中被真实触发。
- 策略来源只批准栏目，没有批准具体话术、产品功能或销售排序；当前仅生成待负责人补充的模板。
- 本轮未联系客户、未写 CRM、未创建商机、未触发营销，也未修改 FORTE 原件。

## 异常路径

- 缺失、额外、错配、同内容冒充、空/损坏/截断来源：来源合同失败。
- 重复表头或 ID、未知中文数字、负数、小数、越界、CSV 注入、第四画像、未知报告项或冲突规则：fail closed。
- 合法阈值、优先级、缺失默认或新样本变异：只更新受影响样本、汇总与工件，不转成格式错误。
- Markdown/CSV 缺行、重复行、locator、分数、标签、分布或边界被篡改：独立 Verifier 转红。
- Planner/Analyst 另有安全校验失败：确定性 Artifact/Effect 仍保留为独立事实，Run 状态不得冒充完成。

## 完成条件

- 两份工件可下载并独立解析；台账逐原始行守恒，Markdown 的动态摘要、画像表、规则账本和边界一致。
- 多标签变体真实应用来源优先级；canonical 继续如实显示 witness 0。
- 原 FORTE 输入字节不变，`external_action=none`，策略仍待销售负责人批准。
- PostgreSQL 重启后 Snapshot、Artifact、EffectReceipt 与 outcome 保持一致。
