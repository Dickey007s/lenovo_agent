# SCENARIO-055：先看交付，再按需核对依据

| 字段 | 内容 |
| --- | --- |
| 用户 | 需要拿办公资料得到可复核交付、但不熟悉 Agent 术语的业务同学 |
| 触发 | 当前任务已经形成分析、文件或部分成果，用户打开“查看成果” |
| 痛点 | 引用与长说明堆满页面；保存/采用容易被误读为业务正确；后排待决容易遗漏 |
| 目标 | 一眼找到交付和必须处理的事项，能回开依据，错误不得以绿色保存记录掩盖 |
| 来源 | USER-FEEDBACK-20260922-RESULT-ACCEPTANCE；RUNTIME-20260922-RESULT-ACCEPTANCE |
| 状态 | Limited Verified，117 项原系统浏览器与 49 项受控 Runtime 通过；跨领域结论验收失败保留 |

## 主路径

1. 在原办公资料库输入自己的目标并选择输出方式，经原 POST /runs 启动。
2. 在原能力页查看进展；有成果时进入专注成果内容区，不另开一个 Demo。
3. 财务文件先看金额、期间、条数、下载和财务待复核；长计算/核对说明按需展开。
4. 模型分析先看事实与影响。普通依据默认收起，键盘或鼠标展开后可打开原审查页。
5. 首屏默认前三条普通发现，但所有真正待决定的发现都可见；再展开其余发现时内容完整。
6. 阅读依据不发模型调用；返回核对页、成果和进展沿用原焦点恢复。

## 三条验收

| 用例 | 输入与过程 | 完成条件 | 本轮结果 |
| --- | --- | --- | --- |
| 单项办公 | 三期往来原表，规划/分析后生成 2026 两张明细和三期说明 | 下载字节、金额、每行位置、期间与独立复算一致；原表不改 | 固定范围通过；财务处理仍待人工 |
| 跨领域协作 | 产品、搜索、UX，三根工作包及两个依赖工作包 | 所有工作包有可靠交接和可核对的正确结论 | 未通过：仍等待，且已采用文字有数字错误 |
| 局部恢复 | 受控 Worker 两次结构失败，另外两根已形成真实 v1，然后停止 | 原 /continue 只处理该分支；父结果不变；重放不多调用 | 受控 Runtime/API 通过，不是真实 Provider 恢复或 PG 重启 |

## 异常路径

- 资料引用缺失：仍显示真实数量，但不可用项明确标记，不猜来源、不自动接受。
- 第五条及后续条目需要决定：不得藏在“其余发现”；权威 accepted/stale 不冒充当前 pending。
- 财务文件检查失败：失败说明与下一步默认可见，下载文件并不代表成果可采用。
- 引用歧义或 Worker 修复失败：保留已形成记录，不自动选位置、扩大来源或重跑兄弟分支。
- 真正引用可定位但结论数字错误：独立验收记录失败，不能手改保存的模型输出伪造通过。
- 断网、409、历史只读仍遵守 DR-0032/33/34；此轮未改其后端状态机。

## 前台与后端

前台只改变 ResultView 密度及通过财务文件的解释层级。Artifact/Commit、Result findings、
顶层 DecisionRequest 与现有 DecisionRecord 控制可见状态。所有提交继续绑定 Owner、version、
idempotency 和适用的 source revision。收起不改 Snapshot、不删发现、不授权 Worker。
