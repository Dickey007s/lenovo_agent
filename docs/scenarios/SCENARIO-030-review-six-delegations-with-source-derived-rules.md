# SCENARIO-030：从一份规则和六份委托书逐项推导法务复核清单

## 用户与触发

- 用户：需要批量预审委托书并组织补件的法务、业务负责人和文档管理员。
- 触发：输入“依据统一规则核查六份授权委托书，逐项说明风险、资料不足和复核动作。”
- 痛点：只有模型摘要或固定风险数量时，用户看不到每条规则依据，也容易把文件检查通过误读成可以签署。

## 主路径

1. Planner 在整库冻结索引中自主选择证据；固定 TC-07 效果门另行冻结一份批准规则与六份批准 DOCX。
2. 服务端校验七份来源的逻辑 ID、文件名、路径、allowlist、大小与内容唯一性，并从规则表解析 21 条规则。
3. 服务端解析每份 DOCX 的段落、表格、主体字段、日期、授权范围、转委托、责任条款和包内签署对象；委托人与受托人字段不能互借。
4. 六份文件分别形成 21 条 `triggered/not_triggered/unverifiable` 判断，保留原文位置、摘录、事实、规则判断、责任人、处置动作与退出条件。
5. Runtime 在隔离 Run Workspace 生成结构化 DOCX 和 126 行 CSV，并从批准来源重算后验证来源、规则、覆盖、位置、动态最高等级、摘要、文件结构和只读边界。
6. 前台先显示三个状态：确定性文件/计算检查、法务业务 Gate、签署与人工复核；再允许按六份文件展开 21 条规则。用户下载成果后由法务逐项补件和复核，系统不签署或认定授权有效。

## 当前固定输入结论

- 六份文件均因来源规则命中至少一条高风险项，动态汇总为 6 份高风险。
- 高、中等级规则中共有 11 条关键资料不足：包含关联主体材料、非律师代理资格和律师证号外部核验等缺口。
- 六份签署栏均为空，DOCX 包内没有可审查的 media、drawing、pict、嵌入或数字签名，因此 R05 对六份文件均触发，签署证据为 0/6。
- 委托书 4 缺少受托人身份证或律师执业证号，动态触发 R02/M03；委托书 2、6 有执业证号文本但无 Registry/Connector 回执，M03 为不可验证。
- 三条业务 Gate 均失败，结论为“不得据此签署，必须法务复核”。

## 异常路径

- 缺失、重复或未知来源，空正文，两个逻辑标签指向同一内容：来源合同失败，不生成绿色成果。
- 规则缺失、重复、未知或歧义等级，触发条件为空：规则合同失败，不按旧答案兜底。
- 日期格式非法、起止倒置或同一字段冲突：明确失败或不可验证，不静默通过。
- 关联主体、近亲属/员工关系、法院许可或律师资格外部记录缺失：标记 `unverifiable`，不猜测为通过。
- DOCX/CSV 任一结构、行守恒、位置或动态摘要检查失败：两份 Artifact 与 EffectReceipt 变红，前台不显示可靠成果绿灯。
- Planner/Analyst 另有 Evidence Gap：确定性 Artifact 与法务业务事实保留，整个 Run 可继续处于 `waiting_input`。

## 完成条件

- 两份成果可下载并独立解析；CSV 恰好 126 条唯一文档/规则组合，DOCX 含来源、六份摘要、逐规则台账、人工复核与边界表。
- 所有结论均能追溯到来源规则、来源文件与段落或表格位置；主体字段不串线。
- 来源修复只改变受影响文件；规则等级变异改变相应台账与汇总；旧固定“2 高/4 中”不能通过 Verifier。
- 1440 px 三栏页面按中央内容宽度显示一列或足够宽的文档卡，文件名最多两行；390 px 保持单列，展开规则与页面均无横向溢出。
- 原 FORTE 输入字节不变，`external_action=none`。
