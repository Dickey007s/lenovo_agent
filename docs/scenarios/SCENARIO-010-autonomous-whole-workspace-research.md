# SCENARIO-010：Agent 自主研究整个办公资料库

## 用户与触发

一名需要推进跨文件办公工作的用户，面对一个包含表格、文档、PDF、日志和代码的较大资料库。用户知道想解决的问题，但不知道应该先找哪些文件，也不愿逐项勾选资料。

## 当前痛点

- 手工选文件要求用户先完成本应由 Agent 承担的检索工作；漏选会让结果缺证据，多选又增加上下文和核对负担。
- 按职业或角色分组会把一个连续办公资料库切成多个演示入口，不符合日常文件管理习惯。
- 一次分析结束后只有结论，没有可确认的下一步任务，Agent Control Loop 无法继续推动工作。

## 目标流程

1. 用户在一个文件管理器式资料库中自由搜索、筛选和预览文件，但浏览行为不限定 Agent 的检索范围。
2. 用户只提交目标和 Loop 预算。
3. 服务端冻结完整 allowlisted 文件索引；Planner 读取安全元数据，自主选择本轮最小证据集合并说明原因。
4. 服务端按每轮文件预算编译计划，Analyst 只收到本轮批准文件的安全投影。
5. 前台按轮显示 Agent 选择了哪些文件、为什么选择、模型输出是否被采用、引用是否通过验证。
6. 结果给出最多四个基于本轮资料生成、但尚未逐项验证的下一步任务建议。
7. 只有用户点击“确认并启动”，该建议才成为一个新的独立 Agent Control Loop；旧 Run 和结果不被覆盖。

## 完成条件

- 启动请求不包含客户端文件选择字段，合同冻结完整资料库稳定引用。
- 普通 DOM 不出现职业入口、角色选择、文件勾选或内部路径/hash。
- 每轮读取文件与选择理由来自服务端 Snapshot，不由前端猜测。
- 模型越过每轮文件预算时，服务端确定性保留其高优先级证据并修复依赖。
- 下一步建议在确认前不触发新 Run，确认后用建议原文创建新 Run。
- 结果保持 `review_required=true`，源文件只读，外部动作 `none`。

## 异常路径

| 异常 | 系统行为 | 用户恢复 |
| --- | --- | --- |
| 资料库不可用或完整性失败 | fail closed，不填充静态文件 | 重新读取资料库 |
| Planner 选择超预算文件 | 服务端裁剪到预算并记录选择理由 | 查看本轮实际采用的文件 |
| 模型结构/引用校验失败 | 显示“未采用”，最多一次预算内修复 | 新建 Run 或调整目标 |
| SSE 断线 | GET Snapshot 对账，再以 `after=N` 续订 | 点击重新读取 |
| 建议不合适 | 不启动任何新任务 | 修改任务文本或选择另一建议 |

## 来源与证据边界

- 产品来源：`USER-FEEDBACK-20260825-WHOLE-WORKSPACE-18`。
- 数据来源：FORTE 固定公开版本与 `public-suite-manifest.json`。
- 设计依据：`DR-0024`、既有 ReAct/人机反馈控制研究与本项目 Agent Control Loop。
- 本场景是产品/验收设计，不是用户研究；自动化通过不能证明自主检索质量、任务成功率或用户价值。
