# SCENARIO-039：在同一工作台核对材料并找回暂缓事项

- 状态：Limited Verified，限本场景测试记录与工程路径，验证见 [Evidence](../evidence/DR-0054-DEMO3-COLLABORATION-EVIDENCE-20260919.md)。
- Source：`USER-FEEDBACK-20260919-DEMO3-COMPLETION`
- Decision：[DR-0054](../decisions/DR-0054-demo3-editable-drafts-and-human-judgment.md)

## 场景与来源

项目负责人准备评审材料，两段已获准使用的非敏感文字对截止时间表述不同。需要保留两段原文，再由了解业务的人记录本次采用哪份。参考手册 C11、R06/R10，来源详见[记录](../sources/USER-FEEDBACK-20260919-demo3-completion.md)。

当前痛点是材料对照、人工判断与执行确认容易混为一谈，暂缓之后也不易找回。完成条件为：没有预选；用户明确选择且填写理由后，服务端保存同一事项的判断回执；原材料不变，无后续任务启动。

## 正常路径

1. 在“办理事项”选择“核对材料分歧”，填写标题、材料 A 和 B。
2. 开始后两份内容并排显示，标明用户提供。界面等待用户判断。
3. 用户不能判断时选择暂缓，可以下载人工处理说明；没有自动通知。
4. 办理另一件个人整理，再从最近事项打开原暂缓事项。
5. 用户重新核对、选择 A/B、填写理由并记录。结果显示采用内容及理由，两份输入仍可追查。

这仍是一次“记录判断”的动作。暂缓、恢复和核对不组成多任务自动规划，也不证明多 Worker。

## 异常路径

缺第二份材料：needs_input，只能补齐或取消。修改材料：revision 增加，旧选择与核对失效。尝试普通 confirm：服务端拒绝。保存响应未知：保持原幂等请求，查询/重放，不生成第二条判断。取消后不能再记录判断；Owner 不符返回 404。

最近事项读取失败时显示错误，不填假任务。列表限最近 20 个 Run，不能保证所有历史暂缓项均在其中。内存服务重启会丢失服务端记录；本次不承诺跨设备或生产身份恢复。

## 前台交互影响

桌面材料并排、手机纵向；控制权状态、当前版本和原文可查。先选材料再填理由，没有模型建议诱导，也没有“选择即提交”。业务批准和这条判断记录分别说明。

内部 ID、策略枚举、幂等键不进入主要操作区域。下载说明仅包含当前事项内容和边界，不含原始系统路径。

## 后端事实映射

input.content/alternative_content 是用户提供的材料；office_action.status、decision、receipt、history 为服务端事实。客户端输入选择没有事实效力，只有 record_decision 成功回执才算记录。每次命令绑定 Owner、Run version、action revision 和幂等键。

## 验证与边界

测试覆盖显式选择、理由必填、版本失效、普通确认绕过、暂缓/其他事项/找回，以及桌面和 390 px。自动化不证明业务判断正确、用户理解或效率改善。所有决定仅保存为测试工作区内的内部记录。
