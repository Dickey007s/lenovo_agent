# SCENARIO-062：分清当前交付、历史与业务结论

## 场景与来源

用户：演示 Office Agent 的项目成员及首次查看的业务用户。
触发：输入上线核对要求，或从历史未完成分支发起续办。
来源：[用户反馈](../sources/USER-FEEDBACK-20261010-demo1-clarity.md)、[DR-0075](../decisions/DR-0075-demo1-task-and-delivery-clarity.md)。

## 前台交互影响

1. 在原资料库输入核对任务，不预选 Demo 或客户端来源。
2. 查看本次进展，生成 DOCX/CSV 后立即能看到文件数量，即使 Analyst 尚未生成逻辑简报。
3. 看到“不得上线”时理解为资料核对得出的业务否决，而非没有生成报告。
4. 打开成果阅读、下载，并保留来源与检查入口。
5. 续办时旧成果留在旧记录；新轮尚无成果不表示旧工作丢失。
6. 查看旧轮时明确显示历史，不与当前状态混同。

## 后端事实映射

独立使用文件 Artifact、逻辑版本、business_gate_outcome、Run 和 round_number。
模拟接口不是实际任务完成证据；真实下载不能倒推出整个 Run 完成。

## 验证与边界

正例：通过的文件先呈现。反例：失败文件不计入通过数；无逻辑版本不隐藏真实文件；
子 Run 不继承旧停止状态；历史轮不称当前目标。1920/390px 阅读、业务否决和下载入口保持可用。
真实运行是否完成按 [Evidence](../evidence/DR-0075-DEMO1-CLARITY-20261010.md) 记录，不将单次样本外推。
