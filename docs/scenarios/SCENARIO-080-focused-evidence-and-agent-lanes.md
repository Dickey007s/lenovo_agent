# SCENARIO-080：从任务到原文，再到 Agent 分工

来源：[用户录屏](../sources/USER-FEEDBACK-20261025-blurt-workbench.md)。决策：[DR-0093](../decisions/DR-0093-blurt-focused-workbench.md)。验证：[Evidence](../evidence/DR-0093-BLURT-WORKBENCH-20261025.md)。

## 正常路径

1. 新建任务，输入整理招聘要求；不必从三个常驻案例中选择。打开设置可以看到真实预算，未提交不调用模型。
2. 提交后查看本轮文件、分析工作与引用核对流程。计划描述按需展开，不能把流程节点当作新增模型分工。
3. 在依据列表点击一次“核对这条依据”，直接进入原文件预览和高亮。普通分析不显示业务选择、旧结果或强制复核方案。
4. 结果后的可选建议不是未完成任务；只有确认才创建同一 Task 的后续处理。请求丢失的重试使用原幂等键。
5. 滚动后仍能切换初始处理与后续分支。历史只读、原成果保留；当前目标没有内部背景 JSON。
6. 协作记录中一行一个 Agent，待派发与实际回执分开；依赖后的工作等待真实前序成果。

## 例外路径

- 多候选引用不预选，确认前按钮禁用；关闭/暂缓沿用既有回执和错误机制。
- 人工业务待决、缺源、业务否决、Agent 未完成工作不因减法而隐藏。
- 已返回但未采用、旧 attempt、失败 Worker 不显示绿色交付。
- 建议没有独立理由或直接引用时明确说明缺失，不能猜测薪资/学历是原目标的欠项。
- 暂停、停止、预算到限保留实际控制；不能因隐藏分母而无限调用。

桌面与 390px 检查焦点、滚动、原文高亮、分支可达性、横向溢出和浏览零 POST。受控响应证明 UI 映射，不冒充真实模型本轮执行。
