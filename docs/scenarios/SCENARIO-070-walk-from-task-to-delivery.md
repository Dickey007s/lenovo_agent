# SCENARIO-070：从任务走到成果，再返回待办

日期：2026-10-22。状态：Limited Verified；以 DR-0083 Evidence 的验证范围为准。
用户：首次接触办公资料库、需要核对与交付成果的业务使用者。
来源：USER-FEEDBACK-20261022-USER-WALKTHROUGH；不是形成性用户研究。
目标：在同一原系统辨别“已有内容、当前等待、下一步操作”，无需先理解机制术语。

## 正常路径

1. 筛选和预览资料，填写目标并提交。筛选不限制 Agent 的整库范围。
2. 在执行进展看到已保留草稿；打开成果能看到同一版本，不显示矛盾的空白提示。
3. 返回执行进展，选择一个待办。原文候选不预选；查看位置不提交决定。
4. 打开协作弹窗，先看到要启动哪些工作及预算，再明确确认。
5. 查看哪些结果采用、哪些待核对；同一执行与贡献只占一条主要记录，详细事实仍可展开。
6. 有文件时下载并查看完整成果。文件通过不等于业务批准或全部工作结束。
7. 新建任务打开空白草稿，旧任务保留且不会被停止。

## 异常与保留条件

- failed 文件与受限回执不由旧分析草稿盖过；rejected/supplemental 叙事不重新进入当前结论。
- ready 集合为空，不生成假批次；存在下游阻塞时全部工作仍列出。
- 无 Worker 对应的贡献仍展示；歧义不冒称运行中，也不创建假的人工候选。
- 历史只读、来源变化、输入覆盖限制、未完成项、错误与业务否决保持原合同。
- 手机首屏可见协作确认；原生详情与下拉支持键盘，关闭弹窗后焦点回到入口。
