# SCENARIO-059：在统一工作台切换任务且不被旧响应覆盖

- 状态：Limited Verified，仅统一入口、已测迟到响应隔离和兼容共存；日期：2026-10-07。最终组合浏览器门 149 项通过。
- 用户：在资料研究和单步事项间切换的办公人员。
- 触发：打开历史、准备新任务或查看事项时，上一个网络请求尚未返回。
- 痛点：入口分裂让人误以为存在三套系统；迟到响应可能显示错任务、覆盖草稿或错误恢复旧视图。
- 目标：沿用原工作台与任务上下文，普通查看不执行动作，过时响应不能更改当前选择。
- 完成条件：当前任务/草稿保持正确；未知提交能按原合同找回；旧成果和历史保留。
- Source：USER-FEEDBACK-20261007-UNIFIED-WORKBENCH。
- Decision：[DR-0072](../decisions/DR-0072-unified-workbench-and-response-ownership.md)。

## 主路径

1. 从原资料库创建资料研究，进入任务进展并按需看 Loop/Swarm。
2. 在同一工作台使用既有单步事项入口，明确看到测试记录/未调用模型边界；不新增 Demo 选择器。
3. 暂缓事项后重开历史或创建空白草稿，已有 Run 不被停止、删除或改写。
4. 关闭详情回到原任务视图；有业务写入仅在显式提交并收到服务端合法回执后显示。

## 异常路径

延迟旧 GET/list 或命令响应，在等待期间切换任务/草稿，返回后不能覆盖当前上下文。当前请求失败须保留可见错误。提交结果未知不推断失败，同一请求重试继续复用幂等键；迟到响应不应导致创建重复动作。旧版本按原 409 合同处理，历史保持只读。具体可切换时机仍服从原未保存编辑/未知请求限制。

## 前台交互影响

一份当前任务信息和清楚的下一步，详情渐进展开。待决、业务否决和不完整回执不能藏在普通日志里。内部请求代次、幂等键和原始响应不进入业务界面。桌面与 390 px 须分别检查主操作、返回和内容完整性。

## 后端事实映射

Snapshot 仍是权威；请求代次仅保护前台响应归属。普通分析和 office_action 共用选中 Run 的展示上下文，但动作状态及控制端点不互换。GET 不执行任务，控件选中不等于 DecisionRecord，事项回执不等于真实发件/企业任务。
