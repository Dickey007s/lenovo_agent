# SCENARIO-025：审阅合规外呼流程设计而不误读为已执行

## 用户与触发

- 用户：运营流程设计者、业务负责人、合规负责人。
- 触发：用户在整个办公资料库输入“根据专业性说明生成信用卡 M1 逾期用户 AI 外呼催收流程图文档。”
- 痛点：成果中出现“发起外呼拨号”“写 CRM”等动作词时，用户可能把流程节点误读为执行事实。

## 主路径

1. Planner 从整库冻结索引自主选择《专业性说明.md》，服务端校验只读范围。
2. 固定 TC-10 适配器在隔离 Run Workspace 生成 DOCX，确定性 Verifier 核对 13 项流程规则。
3. 成果区先说明只生成流程设计文档、没有拨号/CRM/短信，再显示文件、来源、六类终态、人工复核原因和下载入口。
4. 用户下载 DOCX，可在文档首部再次看到问题范围、采用依据、执行边界和复核责任；正文含完整流程边和六类终态。
5. Agent 分析与 Evidence Gate 继续独立运行；是否 `completed` 不改变已经通过的 Artifact 事实。

## 异常路径

- 任一确定性规则失败：Artifact 显示失败，不得用模型文字覆盖。
- Provider 输出未采用：保留已验证 DOCX 和 EffectReceipt，模型质量与确定性成果分开报告。
- 外部动作请求：保持 `external_action=none`；当前产品没有拨号、CRM 或短信 Connector。

## 完成条件

- 实际下载 DOCX 可打开，包含一个 START、拨号前 Gate、接通/未接通、频次、录音、身份、第三方、态度、无效通话、转人工和六类终态。
- Artifact 与 EffectReceipt 都显示外部动作未发生。
- 桌面与 390 px 的成果区能看到边界、关键终态和复核责任，且无页面级横向溢出。
