# SCENARIO-046：六项复杂任务逐项记账并从分析失败继续

- 状态：`Limited Verified`；真实 Provider 协议纵切通过，业务正确性仍为 `Draft`
- 日期：2026-09-02
- 决策：`DR-0059`
- 用户来源：`USER-FEEDBACK-20260902-COMPLEX-TASK-REQUIREMENT-ACCOUNTING`

## 1. 目标

产品负责人一次列出六项跨职能核对要求。系统必须让用户看出每一项是本轮执行、已知来源但
延后，还是当前资料库没有来源；Analyst 返回不可采用结构时，合法工作不能一起消失。

完成条件：

1. 六项编号全部进入服务端要求记账，公共 UI 不少项也不虚构第七个业务要求；
2. 本轮执行、延后和缺源数量可分别核对；
3. 延后项保留真实来源与 Branch，可单独继续；
4. Analyst 调用、拒绝、重试、部分采用和停止原因按事件与回执分开；
5. 没有 ready Worker 波次时不显示“继续下一批”；
6. 原文件、互联网和外部系统均不发生动作。

## 2. 可直接使用的输入

> 请基于当前冻结的公开办公资料库，分别核对以下业务分支：
> 1. 产品上线条件；
> 2. 财务跨期风险；
> 3. 法务授权完整性；
> 4. 外呼合规流程覆盖；
> 5. 搜索 Agent 运行可靠性；
> 6. 用户体验问题与优先级。
> 每个分支分别给出当前事实、影响和来源；最后形成跨分支冲突与待决事项汇总。不得搜索
> 互联网，不得修改原文件或执行外部动作。

## 3. 主流程

1. Runtime 冻结 96 份允许输入，识别连续六项显式要求。
2. Planner 查看安全元数据与内部业务标题提示，为六项分别声明状态和原因。
3. 服务端校验完整编号、根单元绑定、依赖、文件 allowlist 与每轮文件预算。
4. 本轮可执行项生成正常 Branch；超出文件预算但已有来源的项生成 waiting Branch；真正缺源
   的项只形成公开缺口，不伪造 Branch 来源。
5. Analyst 只读取本轮批准来源。严格输出失败时最多重试一次；合法 Finding 可部分采用。
6. Evidence Gate 显示完成项、等待项、模型回执与下一步。用户一次只继续一条 waiting Branch。
7. 达到轮次、调用或时间边界时，Run 停止并保留 ArtifactVersion、真实成果文件和未完成 Branch；
   terminal Run 只能通过 `/continue` 创建同 Task child Run。

## 4. 前台输出

- 默认进展显示六项原始任务、完成/等待数量和当前成果；
- 完整执行记录只把 `plan.units[]` 计为本轮可执行分支；
- `deferred_requirements[]` 在“已知来源，尚未进入本轮”区域显示，并提供“继续此项”；
- `uncovered_requirements[]` 在“本轮资料缺口”区域显示，并说明没有搜索互联网；
- 协作页只有 `ready_branch_ids` 非空时显示 Worker 确认动作，否则提示回工作进展；
- 事件与模型回执区区分“已调用、未采用、再次定位、部分采用”。

## 5. 失败与恢复

### Planner 漏号、重复或错误绑定

Plan Validator 拒绝候选并允许一次规划修复；仍不合格则安全失败，不自行补造业务内容。

### Analyst 截断、非 JSON、Schema 或绑定错误

记录具体失败分类并进行一次受控修复。两次都没有可采用结果时进入
`recovery_kind=analysis_output`；不显示失败文本为结论。

### 来源只能部分唯一定位

通过的 Finding 进入新的 ArtifactVersion，未通过项保留为 `source_location` Gap；用户只继续
对应分支，其他成果不回滚。

### 文件预算不足

有候选来源的项标为延后，不写成“没有资料”。延后 Branch 不属于 Worker ready wave，需由用户
从工作进展单独继续。

## 6. 当前边界

真实运行证明协议记账、重试和恢复状态可达，不证明六项结论的业务正确性、完整性或用户价值。
编号合同最多 12 项；当前仍是单主机有界 Runtime，外部动作始终为 `none`。
