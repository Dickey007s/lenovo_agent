# SCENARIO-068：先读任务交付，再按需查看执行过程

- 用户：复核办公交付的任务发起人。
- 触发：原首页已经生成发布报告，却需要滚过多层执行摘要才能下载。
- 痛点：重复成果与结论、待办可能在前三项之外，成功终态仍铺满执行细节。
- 目标：先判断业务结论与文件状态，再下载、处理待办或查看过程。
- 正常路径：提交任务 -> 真实文件与业务结论 -> 下载或完整成果 -> 按需展开记录/公式。
- 异常路径：文件失败、业务否决、未完成项保持可见；来源变化/历史只读/查询错误不隐藏。
- 完成条件：查看零新增 POST；当前轮外的未完成项仍能找到；文件下载和原权限不变；手机无横向溢出。
- 来源：[用户反馈](../sources/USER-FEEDBACK-20261022-task-overview.md)，不代表真人实验。
- 前台变化：原首页重排，完整能力页和各业务结果仍保留，不新增任务入口。
- 服务端事实：Artifact、EffectReceipt、Branch、DecisionRequest、Round coverage 与原 Task 指针。
- 版本/Owner/幂等：完全沿用原控制合同；本地展开不是授权或任务状态变化。
- 状态：Limited Verified，限定受控前端与整合回归；[验证](../evidence/DR-0081-TASK-OVERVIEW-20261022.md)。
