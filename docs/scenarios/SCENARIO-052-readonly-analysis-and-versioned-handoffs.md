# SCENARIO-052：只分析资料，并让下游接收已采用摘要

| 字段 | 内容 |
| --- | --- |
| 目标用户 | 整理产品、算法、交互风险待办的办公人员 |
| 触发 | 会前核查多份现有资料，只想看分析，不需要生成附件 |
| 当前问题 | 关键词命中文件生成器；依赖图没有证明上下游传了什么 |
| 目标 | 遵守禁止生成文件的指令；按明确依赖传递已采用摘要，引用仍可追溯 |
| 完成条件 | 无新 workspace 文件；下游输入有前序 ID/版本/范围回执；只有验证通过内容合入 |
| 来源 | USER-FEEDBACK-20260921-CONTINUE-DEMO12；固定公开 FORTE 原文；不是用户研究 |
| 状态 | Limited Verified；真实复跑 4 份采用、1 份原文定位待核对，不是完整业务闭环 |

## 正常路径

1. 在原资料库“新建任务”输入五项只读核查，明确“不生成文件”；先看任务进展。
2. 服务端冻结输出限制和已批准 Plan。确认协作前，显示计划而非已运行 Agent。
3. 用户确认三个独立根工作包。返回、采用分别记账，通过的结果保留为逻辑 v1。
4. 用户确认两个已 ready 下游。它们收到直接前序摘要及版本，同时读取自己批准的原文。
5. 协作页显示前序成果传递；通过的贡献合入新逻辑版本，原 v1 不变。不生成下载附件。

## 异常路径

- 任一父贡献未采用、未调用、Owner 错误、版本缺失或来源过期：派发前拒绝，不消费新预算。
- 下游批准来源不足以覆盖前序：拒绝，不默默扩权。未通过引用核对的下游仍等待，其他成果保留。
- 重复提交同一波次：按同一幂等摘要返回，不把空 branch_ids 当成下一批任务。
- 重启：旧不可变行/digest 保留；追加既有 checkpoint 恢复事件，未完成调用不自动重放。
- 前台缺少真实输入回执：不虚构传递。原结果可复核，不能把“收到摘要”叫作“已正确完成”。
