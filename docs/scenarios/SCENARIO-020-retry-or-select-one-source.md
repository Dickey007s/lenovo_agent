# SCENARIO-020：直接重试一个分支，或选择一个原文位置

## 用户与触发

办公用户提交跨文件核对任务。Agent 已保留完成分支和现有成果，但有三个待处理 Branch：两个只是
分析结构或原文定位未形成可采用结果，一个 quote 在同一批准文件中匹配到多个真实位置。

## 主路径 A：无需业务判断的分支

1. 总览标记该 Branch“无需核对文件，建议重试”。
2. 用户点“继续此分支”，首屏只看到“直接让 Agent 重试此分支”和一个推荐按钮。
3. 用户无需修改文件、无需填内容；可选线索和停下原因保持折叠。
4. 用户点击“继续任务，只重试此分支”。浏览器带 expected version、幂等键和 Branch ID 提交
   resume；若用户填了线索，先提交 versioned steer。
5. 只有该 Branch 进入下一轮，其他等待/完成 Branch 与 ArtifactVersion 保留。

## 主路径 B：需要人确认原文位置

1. 总览标记该 Branch“需要从 N 个原文位置中选 1 个”。
2. 用户打开后先看到为什么需要自己、要选什么以及选择后的影响。
3. 页面不默认选择候选，主按钮保持禁用。用户比较真实候选位置和安全 Preview 后选择一个。
4. 主按钮启用。accept 仍绑定 DecisionRequest、source revision、candidate、Finding、Branch、
   expected version 和幂等键；服务端重算候选后只恢复绑定 Branch。

## 异常路径

| 异常 | 前台反馈 | 后端事实与恢复 |
| --- | --- | --- |
| 用户没有额外线索 | 输入保持折叠，主按钮仍可用 | 直接 resume，不创建空 steer |
| 用户关闭审查页 | 立即返回 Loop | 开放待决项 best-effort defer；失败不锁页 |
| 候选尚未选择 | 主按钮禁用 | 不发送 Decision，不改变版本或预算 |
| terminal Run | 显示“用此分支新建任务继续” | 新 Run POST；不向旧 Run resume |
| stale/409/网络错误 | 显示真实错误并刷新 Snapshot | 不伪造回执，不随机换候选 |

## 完成条件与边界

- 用户能在打开页后区分“授权重试”与“提供原文判断”。
- 一次只处理一个 Branch，点击前没有模型调用或下一轮预算消耗。
- 本场景不证明 Finding 语义、模型下一轮质量、用户理解提升、源文件修改或外部动作。
