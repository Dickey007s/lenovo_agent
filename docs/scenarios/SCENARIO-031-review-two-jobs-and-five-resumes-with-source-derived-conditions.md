# SCENARIO-031：用两份 JD 与五份简历形成可追溯的人工复核建议

## 用户与触发

- 用户：需要初步整理多岗位简历证据、但保留最终决定权的招聘负责人和用人经理。
- 触发：输入“依据两个岗位说明分别审阅五份简历，保留逐条证据并输出辅助筛选结果。”
- 痛点：只有模型摘要或固定通过名单时，用户看不到每条判断来自哪份 JD 和简历，也容易把绿色文件检查误读成录用或淘汰决定。

## 主路径

1. Planner 在整库冻结索引中自主选择证据；固定 TC-06 效果门另行冻结两份批准 JD 和五份批准简历。
2. 服务端校验七份来源的逻辑 ID、文件名、展示路径、allowlist、大小和原始内容唯一性，并从两份 JD 分别解析职责、默认门槛、必要项、优先项、加分项与显式例外。
3. 服务端从每份简历安全文本中解析姓名、学历、明确能力事实和可复算履历年限。候选人身份与字段按各自文件隔离，两个岗位共享来源身份但独立判断。
4. 每个“岗位 × 候选人 × 条件”形成 `met / not_met / unverifiable / human_exception_required`，保留 JD 与简历位置、摘录、事实、判断、原因、责任人、面试或补证动作和退出条件。
5. Runtime 在隔离 Run Workspace 生成两份岗位 DOCX 和一份逐条件 CSV，并从批准来源重算后验证来源、覆盖、状态、动态计数、摘要、隐私与只读边界。
6. 前台先说明“这是人工复核建议，不是录用或淘汰决定”，再分开显示确定性检查、岗位匹配建议和最终 HR 待决；用户可以按岗位与候选人展开具体条件。

## 当前固定输入结论

- 外卖商户 BD JD 解析出 14 条条件，文本评测 JD 解析出 8 条条件；五名候选人形成 110 条唯一判断。
- 当前动态汇总为：有来源支持 32 条、明确不满足 6 条、资料不足 71 条、需人工例外判断 1 条。
- 周伦的文本评测 Python 与 AI 经验必要项有来源支持，进入“建议人工复核”，不是自动录用。
- 孙博文的 AI 相关经历为 8 个月，低于当前 JD 的 1 年必要项；变更该来源事实或合法调整阈值会动态改变相应结果。
- 王琳达的学历低于 BD 默认门槛，但 JD 明示“优秀者可放宽”，因此进入人工例外判断；系统不代替 HR 采用或拒绝例外。
- 赵晨曦简历明确写明 Python、AI 与销售/BD 为无，对应条件可以是 `not_met`；李雨桐和王琳达未陈述的 Python/AI 事实保持 `unverifiable`。

## 异常路径

- 缺失、重复或额外来源，同一内容冒充两份，文件名与简历姓名冲突，空或损坏 DOCX/PDF：来源合同失败，不生成绿色成果。
- 日期非法、履历区间倒置、学历/姓名/年限冲突或 JD 阈值含糊：明确 fail closed，不按旧答案兜底。
- 简历合法但没有陈述某项能力：保留 `unverifiable`，提示补证，不推断为不满足。
- DOCX/CSV 任一结构、唯一键、双来源位置、动态状态、隐私或摘要检查失败：三份 Artifact 与 EffectReceipt 变红，前台不显示可靠筛选建议。
- Planner/Analyst 另有 Evidence Gap：确定性 Artifact 与候选人 outcome 保留，整个 Run 可以继续处于 `waiting_input`。

## 完成条件

- 三份成果可下载并独立解析；CSV 有 110 条唯一岗位/候选人/条件组合，两份 DOCX 各含五名候选人的岗位条件、逐项证据和人工动作。
- 每个判断同时绑定 JD 与简历来源位置；两个岗位、五名候选人及各自主体字段不串线。
- 孙博文经历、JD 年限、李雨桐 BD 事实或王琳达例外条款的测试变异只改变来源影响范围；旧固定名单不能通过 Verifier。
- 输出不包含真实邮箱、手机号、地址、性别、年龄、照片及明显人口属性代理值，并明确没有公平性结论。
- 原 FORTE 输入字节不变，`external_action=none`；没有 ATS 写入、通知、背景调查或自动录用/淘汰。
