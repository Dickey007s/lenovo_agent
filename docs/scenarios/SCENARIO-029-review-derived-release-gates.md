# SCENARIO-029：从四份发布资料推导上线 Gate 并审查整改计划

## 用户与触发

- 用户：需要判断本批次能否上线并组织整改的产品、发布、研发和测试负责人。
- 触发：输入“综合 PRD、上线配置、功能测试和兼容测试，给出上线结论与改进计划。”
- 痛点：单看 93.4% 等测试通过率或硬编码风险名单，无法判断是否真正满足 PRD 条件，也无法追溯每项功能为何被定级。

## 主路径

1. Planner 在冻结整库索引中自主选择材料；固定 TC-11 效果门另行冻结四份批准输入。
2. 服务端按数据合同解析 PRD 18 项功能，以及配置、功能测试、兼容测试各 13 项记录；发现重复、未知、冲突或非法数值即停止。
3. 对 18 项功能建立逐项台账，保留来源行、测试事实、异常环境、命中规则、最终等级、负责人和退出条件。
4. 从 PRD 阈值计算四条正式 Gate。固定样本四条均失败，因此业务结论为“不得上线”；用例通过率只作辅助指标。
5. Runtime 在隔离 Run Workspace 生成结构化 DOCX 和 18 行 CSV，并用九项唯一确定性检查验证来源、公式、台账、文件结构和原件未改。
6. 前台先显示“不得上线”及四条原因，再渐进披露辅助指标、18 项台账和两份下载成果。绿色确定性检查不能覆盖红色业务结论。
7. 用户下载报告和台账，逐项分派整改并人工决定后续是否创建新的复核任务；系统不执行上线或改配置。

## 异常路径

- 来源表头、编号、名称、优先级、状态或数字不合法：只生成失败说明，Artifact/EffectReceipt 不得为绿。
- 兼容环境表头折叠后重复：数据合同失败，不猜测两列的含义。
- 正式 Gate 分母为零：明确失败，不使用兜底分母。
- DOCX、CSV、风险集合或 Gate 复算任一检查失败：保留失败证据并提示创建新的 TC-11 Run，不把已生成文件冒充可靠报告。
- Planner/Analyst 结果还有额外 Evidence Gap：确定性 Artifact 与业务 Gate 事实仍保留，但整个 Run 可保持 `waiting_input`。

## 完成条件

- 两份成果可下载并独立解析；CSV 18 行守恒，DOCX 至少 6 个结构化表。
- 风险由规则推导为严重 4、主要 2、次要 2；五项未提测可追溯。
- 四条正式 Gate 分别为 5/7、4/5、2/5、严重 4 项，全部失败。
- 来源变异会改变风险结果；负向合同和 Verifier 失败不会被包装成绿色结论。
- 原 FORTE 输入字节不变，`external_action=none`。
