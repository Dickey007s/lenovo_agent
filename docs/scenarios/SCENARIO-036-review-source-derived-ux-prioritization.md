# SCENARIO-036：从完整交互日志形成可回溯优先级与待审批方案模板

## 用户与触发

- 用户：需要先看清完整日志覆盖、排序依据和数据质量，再决定是否进入方案设计的 UX 负责人。
- 触发：输入“基于完整交互行为日志和页面规范，给出痛点优先级与优化建议。”
- 痛点：旧实现只分析 120 行 Preview，漏掉后 92 行中的 21 组，同时把固定建议和 6 项自检显示为绿灯。

## 主路径

1. Planner 在整库冻结索引中自主选择证据；固定 TC-15 效果门另行冻结批准 XLSX、MD 和 DOCX 原始字节。
2. 服务端完整解析 XLSX，逐行保留来源位置、痛点、结果、重试/误触与重复事件事实。
3. 服务端从 MD 解析严重度、频率和矩阵，从 DOCX 解析页面/元素/要求；3% 冲突和映射假设保持可见。
4. 服务端按 page×operation×pain 聚合。每组引用实际采用的来源规则；边界组不猜优先级。
5. Runtime 在隔离 Run Workspace 生成聚合与逐行两份 CSV；Verifier 重读来源和最终 bytes。
6. 前台先说明这是离线排序，不是用户研究或自动修复，再分层显示全量覆盖、P0-P4、contributors/rule refs、待审批模板和未发生动作。

## 当前固定输入事实

- 当前批准 XLSX 为 1 个可见 Sheet、212 个数据行；161 行有痛点，51 行无痛点仍计入全量分母，55 行为成功但有痛点。
- 当前逐行载荷有 192 个唯一值、16 个重复组和 20 条额外重复事件；固定适配器不自行去重。
- 当前动态得到 87 个组合，P0/P1/P2/P3/P4 为 25/40/14/6/2。后 92 行带来 21 个旧 Preview 未覆盖组合。
- 当前规则存在 3% 边界冲突，canonical 没有恰好命中 3% 的组；24 项操作映射是待复核适配器假设，4 个规范元素未覆盖。

## 异常路径

- 来源缺/多/错路径、同内容冒充、空/损坏、多或隐藏 Sheet、宏/外链、非法数值或规范表损坏：来源合同失败。
- 合法新行或同步新增痛点：动态进入分母、聚合和规则引用；未知痛点/操作只保留 manual review，不静默丢弃。
- 恰好命中有冲突的 3% 边界：保存两侧 frequency refs，不应用 priority ref。
- 聚合/逐行 CSV 的分母、计数、规范、规则 refs、边界、行集合或 locator 被篡改：独立 Verifier 转红。
- Planner/Analyst 另有安全校验失败：确定性 Artifact/Effect 作为独立事实保留，Run 状态不得冒充完成。

## 完成条件与边界

- 两份 CSV 可下载并独立解析，212 行守恒、87 组和每组 rule refs/contributors 可追溯。
- 原始三份输入字节不变，`external_action=none`；方案、生产 UI、发布和实验均未发生。
- PostgreSQL 重启后 Snapshot、Artifact、EffectReceipt 与 outcome 一致。
- 当前只覆盖固定 `uiux-021` 离线排序适配器，不是用户研究、线上遥测、设计效果证明、通用分析、自动修复或生产发布。
