# SCENARIO-033：从批准说明推导可遍历外呼流程并等待审批

## 用户与触发

- 用户：需要先形成可核对流程设计，再交业务与合规负责人审批的运营人员。
- 触发：输入“根据专业性说明生成信用卡 M1 逾期用户 AI 外呼催收流程图文档。”
- 痛点：旧实现的固定流程和固定检查会在来源改变后继续自绿，用户也容易把文档里的“拨号”“写 CRM”“短信”误读成已经执行。

## 主路径

1. Planner 在整库冻结索引中自主选择证据；固定 TC-10 效果门另行冻结唯一批准 Markdown 原始字节。
2. 服务端校验逻辑 ID、文件名、展示路径、allowlist、声明大小与 file ref，再按安全行号解析监管约束、业务分支、最终状态和 AI 行为说明。
3. 每条规范拆成原子要求，绑定动态参数、来源位置与期望动作；未知或冲突规范停止，不跳过。
4. 服务端生成稳定 ID 状态图，校验唯一 START、可达性、终态、关键顺序、第三方与身份边界，以及每条要求的映射覆盖。
5. Runtime 在隔离 Run Workspace 生成结构化 DOCX；Verifier 重读批准 Markdown，并重新解析 DOCX 六类表格与摘要逐字段核对。
6. 前台先说明这是待审批流程设计，再分开显示确定性检查、规则覆盖、最终审批和真实动作；用户可以展开规则查看 locator 与映射节点。

## 当前固定输入结论

- 当前批准版本动态解析为 15 个规则组、34 条原子要求。
- 图包含 31 个节点、36 条边、7 个守卫、7 个终态；7/7 从唯一 START 可达。
- 来源列出 6 类业务终态；系统另保留“身份无法确认结束通话”的安全终态。
- 当前关键顺序是“身份确认 -> 录音告知与来意 -> 欠款引导”。
- 本轮未拨号、未写 CRM、未发短信、未写禁呼名单、未实际转人工，也未取得最终合规审批。

## 异常路径

- 缺失、额外或错配来源，空、二进制、截断 Markdown：来源合同失败，不生成绿色成果。
- 重复或冲突规则、非法时间或数字、未知规范：fail closed，并说明规则覆盖缺口。
- 新增可识别转人工条件：规则、守卫与路径动态增加；新增无法到达的终态：图完整性转红。
- DOCX 表格、边、顺序、终态、rule ref 或 locator 被篡改：独立 Verifier 转红。
- Planner/Analyst 另有 Evidence Gap：确定性 Artifact 与 outcome 保留，Run 仍可诚实处于 `waiting_input`。

## 完成条件

- DOCX 可下载并独立解析，规则、节点、边、守卫、终态、来源位置与覆盖矩阵可由批准 Markdown 重新推导。
- 合法来源参数变异只改变相应参数；新增已支持转人工触发只改变相关规则和路径。
- 原 FORTE 输入字节不变，`external_action=none`；最终审批和所有外部动作均未发生。
- PostgreSQL 重启后 Snapshot、Artifact、EffectReceipt 与 outcome 保持一致。
