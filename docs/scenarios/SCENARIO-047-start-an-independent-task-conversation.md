# SCENARIO-047：从当前工作进入一个独立新任务

- 状态：`Limited Verified`；前台工程纵切通过
- 日期：2026-09-03
- 决策：`DR-0060`
- 用户来源：`USER-FEEDBACK-20260903-NEW-TASK-CONVERSATION-ENTRY`
- Evidence：[`DR-0060-NEW-TASK-CONVERSATION-EVIDENCE-20260903`](../evidence/DR-0060-NEW-TASK-CONVERSATION-EVIDENCE-20260903.md)

## 1. 目标

用户正在查看一个当前或历史任务，希望开始另一项独立工作，同时保留上一任务和全部历史。

完成条件：

1. Workspace 和 Agent 能力页都能直接新建任务；
2. 点击后立即得到空白、可编辑且聚焦的任务输入；
3. 点击本身不创建 Task/Run、不调用模型、不停止旧 Run；
4. 刷新仍停留在新任务草稿，而不是自动恢复旧 Run；
5. 从任务会话仍能返回旧任务；
6. 启动后服务端返回独立 `task_id/run_id`，历史新增一项任务；
7. 连续提交相同文字仍使用不同幂等键。

## 2. 主流程

1. 用户打开一条当前非终态 Run，页面正在接收 SSE。
2. 用户点击“新建任务”。
3. 浏览器关闭 SSE、清空当前选择并显示“新任务草稿”；旧 Run 没有收到控制命令。
4. 用户可打开任务会话确认旧 Task 仍在，然后关闭抽屉继续填写目标。
5. 用户点击“启动 Control Loop”。
6. 浏览器发送一次新的 start command；服务端创建独立 Task 和 Run。
7. 合法 Snapshot 清除草稿标记，新 Task 出现在任务会话列表。

## 3. 刷新与失败

- 草稿模式刷新：重新读取最近 Run 供历史抽屉使用，但不自动选中旧 Run；
- 启动失败或结果未知：保留新任务草稿；未知结果重试沿用本次 command key；
- 打开旧记录：清除草稿标记，依 Task current pointer 决定实时或历史只读；
- 旧 Run 后台变化：草稿不订阅其 SSE，用户返回或刷新历史时再读权威状态。

## 4. 非目标

本场景不实现空会话服务端记录、草稿同步、任务标题编辑、删除任务、停止上一任务、无限历史
或跨 Owner 会话。
