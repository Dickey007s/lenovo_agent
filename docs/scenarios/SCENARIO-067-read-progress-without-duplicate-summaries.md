# SCENARIO-067：不用重复阅读就找到进展与待办

- 用户：负责阅读办公分析结果和确认局部待办的业务人员。
- 触发：打开已完成任务，或查看多个工作包的协作状态。
- 痛点：成果与分支重复，统计在图之前，难以区分主要内容和辅助回执。
- 目标：先找到业务结论、依赖关系和当前动作，再按需核对来源及回执。
- 完成条件：不丢失待办、拒绝与恢复控制；普通详情可访问且不触发业务请求。
- 来源：[用户反馈](../sources/USER-FEEDBACK-20261022-reference-ui-refinement.md)。单一反馈，不是用户研究。
- 决策：[DR-0080](../decisions/DR-0080-reference-led-information-hierarchy.md)。
- 证据状态：Limited Verified，范围与最终结果见 [Evidence](../evidence/DR-0080-REFERENCE-UI-20261022.md)。

## 正常流程

1. 从原工作台打开完成任务；先看到文件数量、业务结论和查看成果入口。
2. 不再重复显示全已完成的分支清单；从原执行区查看详细历史。
3. 打开协作方式；先看真实工作包依赖及当前影响。
4. 展开执行回执；可分别核对调用、采用、贡献与来源，关闭后回到图。

## 异常流程

- 任一分支未完成：原交付清单仍保留，不把未完成跨轮分支删掉。
- 文件检查通过而业务否决：默认层保持“不得上线”等业务拒绝，不显示绿色无待办替代它。
- 无完整确认候选：保持原失败/等待解释，不自动选项或伪造可提交决定。
- 历史只读、来源变化与网络未知：沿用原可见警告与禁用规则。

## 服务端与前台

只读取 branches、workspace_artifacts、work_units、worker_runs、contributions 和原决策状态。
折叠、切换与成果阅读不改变服务端 Snapshot；控制仍要求原 Owner、版本和幂等键。
内部标识和原始模型内容仍不公开。本轮不改后端协议。
