07-16 把三个 Demo 分成时间连续性、复杂任务组织和动作风险。这个分工保留不变。当前版本真正补上的，是把每个演示的进展落到资料范围、分支证据门、工作包依赖、贡献采用、成果文件和未执行边界。Demo 2 不再只有目标框图：服务端可以编译受控工作包依赖图，并以单进程、顺序批次、每批最多三个只读执行单元形成有限纵切；它仍不是分布式协作运行时。对用户而言，界面不再只说智能体正在运行，而要说明为什么停、从哪里继续、谁依赖谁、哪一批需要确认、确认后会改变什么。这里的设计依据来自 Microsoft HAI Guidelines 对能力边界、上下文和纠正控制的要求，以及 ReAct 对环境反馈循环的启发。它们支持设计方向，不证明当前方案优于竞品。
