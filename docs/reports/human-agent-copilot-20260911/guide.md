# 人机共驾指导手册 v0.1

日期：2026-09-11。状态：`Draft`，用于 Demo 3 方案评审。不是风险合规意见、通用审批系统或外部执行授权。

## 1. 场景与来源

本轮来自会议反馈：系统化梳理不同风险等级与接管方式；形成多场景、多边界类型的 Demo 3；沉淀指导手册；三个 Demo 完成后再进行一轮技术时效性调研。反馈和五张参考图属于 stakeholder 设计输入，不是目标用户研究。来源 ID 与边界见 [sources.md](sources.md)。

目标用户不是“所有知识工作者”的抽象集合，而是负责交付跨职能报告、业务核对或事故复盘的任务负责人，以及拥有特定审批职责的产品、财务、HR、客户运营和运维负责人。Agent 负责范围内研究、候选形成与恢复；人负责无法由确定性证据替代的业务判断。没有动作权限时，两者都不能通过界面绕过硬门。

## 2. 核心决策

Demo 3 是 Demo 1/2 的跨拓扑约束，不另立 Runtime：

`用户目标 → 现有 Task/Run → Agent Control Loop 或受限 Workers → 服务端证据与权限边界 → 最小人工处置 → 版本化回执 → 局部继续 → 新成果版本`。

需要同时回答三类判断：证据能否支持采用；谁承担业务判断责任；动作是否被允许。执行发生后还有独立的结果回执问题。不能让“文件通过”“模型置信度高”“负责人点击确认”替代其中任何一项。

R0–R3 是本包的设计候选分类，不是 NIST 标准中的既定等级，也不是现有 Runtime 的通用 `risk_level` 实现。分级由明确的影响、可逆性、敏感性、授权与来源状态共同决定；遇到未知关键条件不默认为低风险。硬性禁止优先，不能把一个高风险维度与多个低风险维度求平均后放行。

| 候选层级 | 典型条件 | 交互方式 | 人的责任 | 当前实现边界 |
| --- | --- | --- | --- | --- |
| R0 范围内推进 | 批准的只读范围，低影响，可检查，没有未解决阻断 | 非打断状态提示、随时暂停与查看 | 抽查结果和目标偏移 | 当前有界只读控制基础；非通用自动风险分级 |
| R1 局部确认 | 位置歧义、可恢复结构失败、预算续办 | 一项一动作，成果先保留 | 选位置或授权一次有限恢复 | DR-0032/34/53/55/59 的有限合同 |
| R2 业务责任 | 来源规则冲突、敏感业务判断、请求外部动作 | 证据对照、初始判断、可选建议、后果预览 | 有职责的业务负责人确定口径 | 当前业务选择/固定 Gate 可复用，外部执行未接入 |
| R3 专业接管 | 高影响、不可逆、生产目标不明或恢复条件缺失 | 阻断执行、整理交接材料、升级责任人 | 专业授权系统内处理 | 通用风险门与外部执行为设计候选，不可伪造 |

## 3. 八条可复用规则

| 规则 | 触发 | 必须行为 | 禁止行为 |
| --- | --- | --- | --- |
| R-01 权限先行 | Connector 不存在、范围未批准或目标不明 | 阻断动作；可保留研究材料；明确人工转交 | 确认后临时创造权限、伪执行成功 |
| R-02 原文消歧 | 服务端 Resolution 有多个真实候选 | 不预选；并排上下文；接受时校验 revision/candidate/version | 模型猜位置、客户端猜行号、以选择证明语义 |
| R-03 业务口径 | 有明确相反来源且影响决策 | 显示两侧与责任人；先形成自己的口径，再按需看建议 | 让模型建议等于批准；由无 contradiction Anchor 的普通发现制造阻塞 |
| R-04 高影响门 | 不可逆、敏感或关键生产条件未知 | 保持阻断并交专业责任人；保留预检与恢复条件 | 风险平均降级；用双勾选模拟生产审批 |
| R-05 有界续办 | Run 终态但还有未完成 Branch | 同 Task child Run；双版本保护；重核选定来源；保留父 Run | terminal resume、隐式加预算、静默带入旧模型结论 |
| R-06 Agent 自有修复 | 结构/定位输出失败但源范围合法 | 显示已调用未采用；无需用户改文件；只授权一次有限恢复 | 无限重试、把系统缺口写成用户材料错误 |
| R-07 局部协作收敛 | Worker 返回但 Contribution 未采用 | 已采用兄弟成果保留；目标 Branch 与依赖等待 | 返回等于采用、多数票绕过证据 Gate、空 ready wave 派发 |
| R-08 双状态成果 | 文件检查通过，但业务 Gate 未过 | 同时显示文件与业务状态，业务失败不能被绿灯遮盖 | 文件通过等于可上线/可签署/可通知客户 |

规则顺序：先权限和硬性影响条件，再证据与业务责任，再预算/版本，再核验回执。对于已明确禁止的动作，不应诱导用户先解决证据问题后再发现“仍不能执行”。

## 4. 前台交互模式

首屏固定说明：为什么需要人；只影响什么；已有成果保留什么；由谁决定；唯一推荐下一步。按服务端 ID 连接 Branch、材料、Evidence Gate 与动作。源文件、回执和内部字段在需要时展开，普通用户不先读技术诊断。

位置选择使用单选，不预选；两处位置展示相同引用周围的不同上下文。选中之后才能确认。单纯 Agent 结构失败不显示候选单选，更不强迫用户填答案，只提供局部重试。权限不足不展示“同意并执行”，只允许明确的人工转交，且意向记录不得说成交接已送达。

业务选项把“不符合当前规则”与“先调查是否有批准例外”分开。推荐仅在用户形成初始口径后按需展开，以免默认选项替人作决定。确认只记录决定；后续独立任务启动仍遵循当前真实合同。

关闭与 Escape 先退出，随后尝试 defer。即使 409 或断网也不能把人困在审查页。成功回执之前只能显示请求、未确认或结果未知；失败后保留已显示的旧状态并刷新权威事实。此包沙盘没有真实回执，因此始终只说“本地意向”。

“恢复”指有界恢复，不保证成功。合法 waiting Run 使用目标 Branch resume；terminal Run 只能创建同 Task child Run。来源变更重核，旧候选选择清空；历史成果保留，不自动迁移旧采用结论为当前事实。

| --- | --- | --- | --- | --- |
| B01 产品负责人 | 相同引用重复出现；用户不知道选哪处；目标是定位正确上下文 | 比较两处→选择→版本化接受→仅恢复交互评估；真实完成需 DecisionRecord 和新回执 | 无选择禁用；过期清空；409 刷新；断网结果未知 | S-LOCAL-DECISION、S-USER-UI；案例 Draft，机制已有有限基础 |
| B02 业务负责人 | 规则要求人工发送但运行观测相反；目标是决定当前评审口径 | 看两侧→初始口径→可选建议→记录；后续调查另行确认 | 例外材料缺失保持开放；没有 contradiction Anchor 不制造阻塞 | S-LOCAL-GOVERNANCE、S-HAI；Draft |

| B04 运维负责人 | 请求清空生产索引，端点和恢复条件未知；目标是防止错误执行 | 离线提案→核对目标/备份/责任→授权系统内专业接管 | 所有线上连接和 HTTP/ES 命令保持禁止；普通确认不可绕过 | S-LOCAL-EFFECT、S-NIST；Draft |
| B05 任务发起人 | 预算终态而业务分支未完成；目标是保留历史并续办 | 选择一 Branch→双版本 continuation→同 Task child→重核来源 | 409 留在父 Run；当前指针未查明不猜新 Run；旧 Run 不 resume | S-LOCAL-LINEAGE；机制有限，案例 Draft |
| B06 任务发起人 | 已调用但结构失败；目标是让 Agent 处理自己的交付缺口 | 无需修文件→授权目标 Branch 重试→等新调用与采用事实 | 预算耗尽转 B05；范围越权/完整性错误仍 fail closed | S-LOCAL-RECOVERY；机制有限，案例 Draft |
| B07 跨职能负责人 | A/B 已采用，C 原文歧义；目标是保留好的工作并局部处置 | 处理 C→Evidence Gate→新版本；真实 ready Branch 才可显式确认下一波 | C 失败不覆盖 A/B；重启不自动重放在途 Worker | S-LOCAL-LINEAGE；机制有限，案例 Draft |
| B08 发布负责人 | 文件通过而业务 Gate 失败；目标是正确解释成果 | 查看报告→复核不满足项→实际批准另行进行 | 模型不同意见不能盖过固定 outcome；来源/文件失败不得以业务文案覆盖 | S-LOCAL-EFFECT；机制有限，案例 Draft |

## 7. 验收与研究协议

工程正例：一处明确引用不弹人工选择；多候选未选禁用；选择后只动目标 Branch；不同业务选项不混同；验证文件与业务 Gate 双状态保留；child Run 同 Task 且父 Run 不变；无权限没有执行控件。

工程负例：409、断网结果未知、来源已变、候选篡改、重复幂等键、历史 Run、预算终态、空 ready wave、无 Anchor、一个 Worker 失败、已通过文件加审计待补充。服务端负例需要在正式 Runtime 测试中验证，沙盘模拟不替代它。

视觉检查：桌面与 390px 手机宽度；文本不溢出；动作可见；候选不默认选中；关闭与 Escape 可达。截图只能支持观察到的像素状态，不能证明服务端事实。

目标用户研究建议：招募不同办公责任角色的 6–8 名参与者进行形成性测试，数量是计划而非已执行。随机化相同任务的旧/新界面顺序，比较能否正确识别受影响分支、保留成果、唯一下一步和外部动作边界；记录错选、错批、误认为已执行、完成时间和解释内容。报告每人原始事件与任务条件，不把小样本偏好外推到总体。高影响误执行认知为关键失败，不用平均体验得分掩盖。

## 8. 技术时效性回溯门

当前只定向核对三个官方来源支持设计；完整回溯尚未启动。触发条件：Demo 1/2/3 通过各自明确的固定验收，冻结 implementation SHA、模型/Provider、预算、数据版本与 UI 截图。在三者冻结后 7 个工作日内启动调研是建议议程，不是已创建的自动提醒。

回溯分别检查：模型结构输出和多模态能力变化；Agent 框架中断/持久化/工具审批与幂等变化；办公产品来源引用、人工控制和结果版本体验变化。只用官方发布、文档和论文建立候选，再固定相同场景和可用配置做同场挑战。记录官方声称、实际观测、仍未知三列，不把文档未写某能力当成产品没有。

替换与不替换都给出可证伪理由：需要解决的失败是什么；改动哪些合同；与旧版本在同一输入下的采用、错误恢复、成本/延迟与用户判断是否改变；哪些测试要重跑；如何退回旧版本。没有可比数据时，仅输出下一轮候选，不声称优越性或时效性已完全保证。

## 9. 实施顺序与交付边界

1. 先完成本次参考 UI 下的 Demo 1/2 真实前端投影与证据核对，复用服务端状态，不另造案例 Runtime。
2. 从 B01/B05/B06/B07 开始，将已有合同投影为统一边界处置模式；同步正式 Decision、Scenario、Source、Evidence 和 UI fact mapping。
3. 在固定能力中接 B02/B08 的业务责任差异，保护文件/业务/运行三状态。
4. B03/B04 只交付阻断与专业接管材料。若未来接外部动作，另立权限与执行设计，先负例再有限试点；普通 UI 确认不可代替服务端权限。
5. 完成形成性用户研究后再决定是否升级规则候选。不得把本 HTML 的本地意向记录称为真实审批或恢复成功。
