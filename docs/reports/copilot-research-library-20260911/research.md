## 2. 六条研究主线

### 2.1 主动权应可转移，不是“自动 / 手动”二选一

Horvitz 的 mixed-initiative 原则关注行动价值、打扰成本、澄清、直接调用与终止。Scerri 等进一步指出，团队中的控制转移要考虑响应时延及协调代价。前者是原则与系统实例，后者有形式化及特定部署系统依据，都不能直接给现代 LLM 办公任务设通用阈值。[S01 原文](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf)、[S02 原文](https://arxiv.org/pdf/1106.4573)

**设计推导：** Demo1 显示待确认问题的影响范围，用户保留主动暂停和调整权。Demo2 在某分支等待时保留其他已采用贡献，显示汇总的真实依赖。Demo3 对比主动提醒、用户接管、延后与责任转交；人的沉默不构成授权，超时不自动放行。

### 2.2 退出权不是弱功能，而是监督合同

HAI 准则将退出、纠错和不确定时缩小服务范围列为设计要求。MCP 固定版本规范区分接受、明确拒绝、未作选择的关闭，并要求妥善处理错误。这些来源支持可退出与语义分离，不规定本项目必须使用某一个协议字段。[S03 准则表](https://www.microsoft.com/en-us/research/wp-content/uploads/2019/01/Guidelines-for-Human-AI-Interaction-camera-ready.pdf)、[S12 规范](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation)

**设计推导：** 关闭先退出界面，写回决定是另一项有可能失败的操作。409 要刷新权威状态；传输失败可能是结果未知，不能断言一定未写入。项目已有 `defer` 与 MCP `cancel` 不是同一合同，不能把参考语义写成已接入 MCP。

### 2.3 合适依赖不是最大化信任，也不是最大化接管

2021 年认知强制实验发现减少错误跟随与主观体验可能冲突；2023 年研究则显示，解释能否降低核验成本会影响其作用。它们不是互相推翻，而是在不同任务和干预中说明“加解释”没有无条件保证。[S04](https://arxiv.org/abs/2102.09692)、[S05](https://arxiv.org/abs/2212.06823)

2025 年知识工作者调查的“信任越高，批判性思考越少”是自报相关，不是认知能力退化的因果结论。2026 年写作计划实验中，假设检查与 WhatIf 的效果、偏好也不一致；该文仍标为预印本。合适依赖研究议程同时关注错误采纳与正确建议被拒绝。[S07](https://www.microsoft.com/en-us/research/publication/the-impact-of-generative-ai-on-critical-thinking-self-reported-reductions-in-cognitive-effort-and-confidence-effects-from-a-survey-of-knowledge-workers/)、[S09](https://arxiv.org/abs/2601.18033)、[S18](https://www.microsoft.com/en-us/research/articles/appropriate-reliance-research-initiative/)

**设计推导：** 歧义时保留无预选，降低原文核验成本；计划假设问题作为可评估的高影响审查候选，而非所有普通重试的必填测验。先让用户形成判断，再显示建议也只能作为待测假设。收集错误接受、错误拒绝、用时、工作负担；满意度和批准率不能替代它们。

### 2.4 多步可见不意味着有效监督，协作也不天然胜过单方

2024 年元分析纳入 2020 年初至 2023 年中研究，区分相对人工的增强与超过最佳单方的协同。整体人机组合未达到后者。不能把创作子组的方向性点估计写成显著正收益，也不能把所有组合都判成无效。[S06 出版原文](https://www.nature.com/articles/s41562-024-02024-1.pdf)

2025 年多步透明事实核验预印本的整体比较没有优于一步流程；误导建议等情境可能获益，额外反思干预也可能增加负担和错误。它研究的是决策工作流，不是多 Worker 运行时。[S17 原文](https://arxiv.org/pdf/2501.10909)

**设计推导：** 当前简化进展、按需执行记录、协作拓扑和专注核对可以降低复杂度，但不能仅据页面结构宣称有效监督。Demo2 要比较同来源、同预算的单/多 Worker；Demo3 要包含错误与正确建议两类题，观察实际中间步骤核验，而不只统计展开次数。

### 2.5 审批原语与真实执行保证必须分开

LangGraph 文档明确恢复会重跑含中断的节点，需要副作用幂等或拆分。OpenAI SDK 提供待决工具调用与可持久化状态，同时要求考虑长期待决定义版本和持久化数据。二者是框架语义，不是本项目已经迁移的实现。[S10](https://docs.langchain.com/oss/python/langgraph/interrupts)、[S11](https://openai.github.io/openai-agents-python/human_in_the_loop/)

Anthropic 工程文章强调简单编排、停止条件、环境反馈，以及多 Agent 的成本和恢复困难。其内部提升数字、运行模型、并行架构不转移为我们的证据。[S14](https://www.anthropic.com/engineering/building-effective-agents)、[S15](https://www.anthropic.com/engineering/multi-agent-research-system)

**设计推导：** 页面必须区分“选定引用”“服务端记录决定”“开始重核”“生成新成果”。非终态 resume、终态同 Task child Run、Worker 显式重试应有不同文案和验收。恢复前显示版本、批准范围及保留成果，不能说“从刚才那一行继续”而实际重新执行更大范围。

### 2.6 人类控制包含权限、责任与组织条件

NIST Appendix C 讨论监督角色、偏差和人机配置的差异。高级 AI 助手伦理报告与作者解读讨论自主性、控制和对非用户的影响；本轮该报告只核验摘要和官方解读，不声称全文精读。2026 WTI 进一步把个人使用能力与组织准备度区分，相关调查模型不是因果效果。[S13](https://airc.nist.gov/airmf-resources/airmf/appendices/app-c-ai-risk-management-and-human-ai-interaction/)、[S08 摘要](https://arxiv.org/abs/2404.16244)、[S08 作者解读](https://deepmind.google/blog/the-ethics-of-advanced-ai-assistants/)、[S16](https://www.microsoft.com/en-us/worklab/work-trend-index/agents-human-agency-and-the-opportunity-for-every-organization)

**设计推导：** 证据状态、动作权限、可逆性、影响范围、人的角色、可核验程度独立呈现。R0-R3 只可作为内部讨论辅助，不由模型自报置信度单独决定。无授权的 CRM、发布、删除或生产命令不执行；“文件核验通过”不能覆盖业务 Gate 失败。

## 4. 建议的评审与实验门

1. **事实门：** 任意 UI 状态能指到服务端事实；草稿、真实回执、业务通过、外部动作不混写。
2. **退出门：** 409、离线、重复提交、来源版本变化下，退出始终可用，不默许、不默认选择、不伪造回执。
3. **恢复门：** A/B 已采用、C 歧义、E 依赖等待；确认后只处理批准范围，历史成果保留。终态须新建同 Task Run，不假装 resume。
4. **核验门：** 同一事实设置定位明确、重复位置、数据冲突、缺少材料、尾部未读等变体，用户能说清哪层未完成。
5. **行为门：** 以任务正确率、误采纳、误拒绝、接管时延、核验耗时、恢复保留率与负担作指标。样本量和阈值在试验设计时预先确定，不补写假数据。
6. **对照门：** 质量评估区分人工、AI、人机；编排评估区分单 Controller 与多 Worker，冻结任务、模型、来源和预算。高风险不可执行动作只在离线沙盘中评估，不能为对照解除权限约束。
