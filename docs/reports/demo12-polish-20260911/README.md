## 实际改变

1. 长任务目标保持紧凑两行，点击标题展开全文；关闭恢复，不截掉用户查看完整目标的能力。
2. 新任务改为完整书写区，显示真实资料数量和原件只读边界；移除重复的空 Run 技术说明。
3. 分支栏按实际数量自适应宽度，单分支不再挤在三分之一页面。
4. 证据核对使用固定底部操作区和可见选择状态，确认失败也显示在操作区；保留未选禁用、预览不批准、退出先返回再 defer。
5. 主工作面的运行控制保留在正常文档流中，避免浮动操作栏遮住已有成果。

## 量化观察

实际浏览器 1280×720 视口中，修改前确认按钮 y=907–953，完全在首屏之外。
修改后 y=662–706，在当前视口内。测量来自可见 DOM，不是 CSS 推测。
这是控件可达性证据，不是用户决策速度、信任或正确率提升的证据。

## 你可以操作的用例

| 用例 | 操作 | 预期 | 失败判据 |
| --- | --- | --- | --- |
| P-01 长任务 | 历史会话打开日志任务 → 点顶部任务标题 → 再点一次 | 全文可读且可收起，不启动新任务 | 文字无法展开、超出屏幕、调用数增加 |
| P-02 人工核对 | 确认引用位置 → 向下查看候选 → 只点在文件中查看 | 暂缓/确认始终可见；未选时确认禁用 | 必须滚回顶部找按钮；预览自动批准 |
| P-03 草稿 | 协作方式 → 新建任务 → 输入但不提交 | 空白书写区聚焦，原任务仍在历史 | 意外调用模型、旧成果消失 |

已有实际日志任务可以用于只读验收，不必重新调用 Provider。
本轮没有新真实模型调用，也没有改变 Runtime、API、源文件或审批权限。
