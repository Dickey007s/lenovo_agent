# Demo1 / Demo2 / Demo3：边界、案例与阶段进展

2026-09-12。本稿用于会议口头汇报，不是新产品入口，也不把设计写成已完成能力。

## 一分钟可以这样讲

这轮不是新做一套演示，而是在原办公 Agent 系统上继续完善。Demo1 保证任务能跨轮、跨 Run 接着做，保留之前成果；Demo2 研究复杂任务怎么拆给多个受限 Agent，哪些返回能真正进入最终成果；Demo3 则在这两项能力上明确人机决策边界：什么时候系统应该自己补做，什么时候必须问人，以及人的一次确认究竟允许什么。

我们已经把调研落成了八个办公案例，分别列出触发条件、系统可做和不可做的事情、人的动作、恢复范围及失败判据。不是再用固定 L0-L5，而是综合看后果、证据、权限、版本和回执。例如，原文定位失败不应让用户修文件；业务规则冲突不能靠选一个引用位置解决；报告生成成功也不等于允许上线。

在实现上，原任务进展页已增加第一部分人机边界说明，协作页显示服务端准入原因、实际调用和采用数量；原 Control Loop、依赖图、成果历史和核对入口都保留。这里完成的是既有状态的前端整合，不是通用业务审批或外部执行闭环。蜂群的差异候选是来源受限、贡献核验、局部恢复与长期成果历史的组合，尚不能宣称新算法或优于竞品。

## 1. 三个 Demo 不再混在一起

| Demo | 回答的问题 | 典型镜头 |
| --- | --- | --- |
| Demo1：时间连续性 | 怎么接着做，不丢以前的工作？ | 预算结束后，只对未完成分支创建同 Task 新 Run，旧成果不变 |
| Demo2：组织协作 | 为什么分工，谁依赖谁，谁的结果可用？ | 三份 Worker 返回，两份采用，一份歧义只影响真实下游 |
| Demo3：人机边界 | 这一步谁能决定什么，决定改变后怎么办？ | 区分补做、选依据、确认计算、业务规则未通过和禁止外部执行 |

**Demo1 的暂停/恢复是执行机制，Demo3 要定义使用机制的理由、责任和后果。** 不能因为有暂停按钮，就说人机边界设计完成了。

## 2. “危险程度”怎么看

保留“后果严重程度”这个维度，但不把它做成统一自动驾驶等级，也不只靠模型自报置信度。下面是用于案例评审的定性标注，**尚未实现自动评级，也不替代原材料中的业务风险等级**。

| 后果标签 | 办公例子 | 还必须检查什么 |
| --- | --- | --- |
| 轻微、内部可重做 | 重读日志、重新定位、生成隔离草稿 | 即使后果轻微，来源越权或材料不完整也不能冒充成功 |
| 显著、会影响判断 | 错引 PRD、错误排序、错误跨职能风险结论 | 依据是否冲突、哪些下游受影响、谁能确定业务口径 |
| 严重、对外或难撤回 | 发客户、生产上线、签署、付款 | 有无真实能力和权限、具体对象/内容版本、执行回执及补偿；当前不支持执行 |
| 未知 | 未读完材料、证号不可核验、动作回执丢失 | 先补证或核对状态，不能因不知道就按低风险放行 |

然后分别决定：继续、提示限制、澄清一个问题、暂停目标部分、拒绝/交有权人员处理。**同一报告可以允许内部生成、要求澄清规则、同时禁止外发。** 没有“一到某等级就全部接管”的固定对应关系。

## 3. 八个任务镜头与应对

| 任务镜头 | 遇到什么边界 | 应对与案例结果 | 当前程度 |
| --- | --- | --- | --- |
| 财务摘要缺表格位置 | Agent 执行能力缺口 | 先保留已生成文件，只重试定位，不让用户修改原表 | 既有恢复合同，本轮补解释 |
| PRD 同句多处出现 | 证据有多个真实候选 | 人对照上下文选一处；无默认项，来源过期需重新核对 | 既有决定合同，本轮补解释 |
| 长日志后半段有反例 | Agent 未读完却可能给完整结论 | 标明未读范围、续读后再作完整性判断；不能请人替未读内容背书 | 覆盖/续读未实现，Q-01 仍开放 |
| UX 频率恰好 3% | 来源规则冲突 | 明确计算保留，冲突组不套优先级；业务负责人定口径 | 冲突检测已有，规则批准未实现 |
| 上线报告文件通过检查 | 文件正确不等于业务允许上线 | 同时展示报告可审查和业务 Gate 未通过；不提供假上线按钮 | 双状态已有，本轮补边界说明 |
| 委托书有律师证号 | 有字段不等于能核验真实性 | 保留“不可核验”，交法务按获准渠道复核，不显示可签署 | 有限检查已有，外部核验未接入 |
| 三 Worker 一条歧义 | 贡献采用和依赖传播 | 两份贡献保留，未采用项不混入简报，只阻塞真实依赖 | 有限 Swarm 已有，本轮补回执事实 |
| 要求把报告发客户 | 超出现有动作权限 | 保留内部成果，明确未发送；不能把确认依据当外发授权 | 外部执行不支持，仍属设计边界 |

完整的“触发事实 → Agent 可做/停止 → 人的动作 → 恢复与依赖 → 已有/待实现 → 负向用例”见 [八案例指导稿](../research/DEMO3-BOUNDARY-RULES-AND-CASES-20260912.md)。这是产品设计参考初稿，不是已验证的用户行为规律。

## 4. 论文具体改变了什么设计

根据后续反馈，研究主线从界面和信任评估转向 **LLM Agent 的决策、学习和执行控制**。现整理为 [16 篇 Agent 相关论文](../research/DEMO3-AI-AGENT-BOUNDARY-LITERATURE-20260912.md)，包含既有来源重分类，不是 16 篇全部全文精读。

- [SAGE-Agent / Structured Uncertainty，Findings of ACL 2026](https://aclanthology.org/2026.findings-acl.2028/)：围绕工具参数与候选方案选择澄清问题。项目应区别“Agent 没做成功”和“业务口径未给出”，只把后者交给人补充。
- [HiL-Bench，2026](https://arxiv.org/abs/2604.09408v4)：直接评测 Agent 是否知道何时求助。项目不仅检查能否暂停，还要检查该问未问、无谓打扰，以及回答是否真正解决阻塞。
- [SWEET-RL，2025](https://arxiv.org/abs/2503.15478v1)：用分步评价训练多轮协作推理。项目应把澄清、反馈利用、局部修正和再验证看作完整轨迹，不以“收到反馈”代替任务改变；当前没有进行训练。
- [AgentSpec，ICSE 2026](https://arxiv.org/abs/2503.18666v3)：将触发条件与执行约束放在 Runtime，而不只放在提示词里。高置信度、已生成报告和确认依据都不能覆盖真实动作权限。
- [Collaborative Gym，ICLR 2026](https://arxiv.org/abs/2412.15701v6)：围绕同一工作环境研究人、Agent、工具的双向协作。Demo3 应进入原 Task/Run 与成果流程，不另做一套展示系统。
- [Intelligent AI Delegation，2026](https://arxiv.org/abs/2602.11865v1) 与 [MAST，2025](https://arxiv.org/abs/2503.13657v3)：分别提供委派约束框架和多 Agent 失败分类。Demo2 除分工，还要说明权限不扩张、返回不等于采用，以及错误是否传播到下游。

Cocoa、Plan-Then-Execute、When Should Users Check? 与 AGDebugger 保留为交互负担、误纠正及用户理解的辅助文献，详见八案例指导稿。上述设计是论文到本项目的推论，**不是已经接入论文算法、验证用户效果或证明创新性**。逐篇版本、阅读位置、适用范围及反例见新的 16 篇台账；其中 Intelligent AI Delegation 已追加框架和权限/验证章节的定向阅读，仍不宣称全文精读或复现。

## 5. 蜂群的实际差异

准确说是：**主控拆分 → 服务端准入 → 确认最多三个只读 Worker → 每份贡献核验 → 只合并获准内容 → 局部恢复并保留历史。**

“多个 Agent 分工汇总”是主流模式，不是我们独创。当前值得继续验证的是：任务结构和来源约束共同决定分工；返回与采用分离；故障处理能否不重复其他工作；这些保证能否在同一长期任务与成果历史中持续成立。

本轮已在原协作页把准入、实际调用、采用/拒绝/等待数量前置，修正单主控被误写为固定流程，以及 ready 工作包在进展页被误写成正在执行的问题。但还没有同配置竞品对照，**不能报告质量提高多少、成本降低多少或学术算法创新**。机制、源码、演示顺序和对照实验见 [蜂群机制与差异说明](../research/DEMO2-SWARM-MECHANISM-AND-DIFFERENTIATION-20260912.md)。

## 6. 用户能否看懂，要这样测

不先讲解界面，让未参与设计的人回答四个问题：现在什么已经做成？为什么需要我？点击后改哪里、保留哪里？会不会对外执行？

重点反例是：报告文件已经生成但不得上线、三个 Worker 返回但只有两份采用、选了依据但没有业务授权、暂缓/过期/响应未知不等于成功。记录第一回答、误批准、误拒绝、提示次数和总时间，而不是只看点击是否通畅。

本轮自动化及截图范围见 [整合 Evidence](../evidence/DR-0063-INTEGRATED-BOUNDARIES-AND-SWARM-FACTS-20260912.md)。尚未开展真人理解测试、真实 Provider/数据库联合演示；新增边界说明不修复长文本覆盖问题，也不新增业务审批、外发或生产权限。

正式入口仍是启动后的 [办公资料库](http://localhost:3000/) 与 [Agent 能力页](http://localhost:3000/agent-capabilities)。原任务记录、成果、Control Loop、Adaptive Swarm 都保留，没有新增 Demo 选择器、替换 Runtime 或外发按钮。
