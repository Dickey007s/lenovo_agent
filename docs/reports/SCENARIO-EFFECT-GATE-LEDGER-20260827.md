# 场景效果账本：Agent 最终给用户交付了什么

这份账本用于汇报“系统产生了什么可检查影响”，而不是再用架构名、`completed` 或引用数量代替效果。当前资料全部来自 FORTE 固定公开输入，原始文件只读。

## 汇报口径

每条场景分三层讲：

1. **模型层**：Planner/Analyst 是否真实调用，返回是否被采用。
2. **效果层**：是否生成真实文件，数值、字段、排序、规则或测试由哪个确定性 Validator 复核。
3. **控制层**：Run 是 completed、waiting_input、failed 还是外部边界；已经保留什么，下一步由谁决定。

三层不能互相替代。模型未采用不删除已验证文件；Artifact 通过也不把额外分支写成 completed。

## 前台如何让用户看见 Agent 的影响

- 成果文件以独立区域出现，显示文件名、类型、大小和检查通过数，不埋在聊天长文中。
- 点击“查看逐项检查”可以看到每条代码复核事实；点击“查看效果回执”可以看到 Agent 做了什么、观察到什么、花了什么、结果是什么。
- 下载按钮读取真实 Artifact bytes；没有 Artifact 的外部边界不显示按钮。
- “原始 FORTE 文件没有被修改”和禁止副作用直接可见。
- 右侧模型回执继续显示 called/output_used/elapsed；它不被成果卡的绿色状态覆盖。
- 如果额外分支仍待处理，用户仍能从 Branch lane 处理；已验证成果不会消失。
- 当已验证成果与来源定位缺口同时存在时，成果和下载先出现；同一来源影响的多个内部 Gap 合并为一个“不影响成果”的审计项，但底层 Branch 和 Run 状态不改写。

## 从红灯到通过

1. 首次六场景 live：`0/6`，模型已调用但工具被 Analyst 结构门挡住。
2. 调整执行顺序：`6/6` 生成成果，但只 1 条 Analyst 输出采用。
3. 简化 Analyst 输出合同：TC-05、TC-13 探针均 completed。
4. 增加唯一安全 Unit 重绑：TC-10 completed；TC-15 的模型输出被采用并保留 waiting Branch。
5. 当前六个优先场景均有真实模型采用和效果通过记录；TC-14/15 仍保留额外模型分支等待，这个边界不被涂绿。

## 汇报限制

这套实现证明的是固定 FORTE 数据、固定办公适配器和当前 Runtime 的效果闭环。它不证明任意任务泛化、真实企业数据、用户理解、生产安全沙箱、分布式 Worker、外部 Connector 或业务价值。Demo 2 的多 Worker 自组织和 Demo 3 的跨拓扑风险许可仍是目标能力。
