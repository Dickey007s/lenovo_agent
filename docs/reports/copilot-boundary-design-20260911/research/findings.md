# 从风险标签走向可检验的授权边界

日期：2026-09-11。状态：**Draft，定向增补研究**。资料台账：[sources.json](sources.json)。本次新增 8 项来源，与旧库 18 项不重复；包含论文、真实使用观察、官方协议和工程文档，不是完整行业回溯。

## 1. 结论先行

**不能据本轮证据断言“单一风险等级足以决定交互”，也不能断言我们拟议的“有界授权 + 异常停靠”已经更好。** 尚未找到严格隔离单轴/多轴、其它因素相同的办公 Agent 实验。已找到的直接权限研究反而提示：用户自己写规则、弹窗变少、感觉可控，都不能单独证明越界更少。

历史定位材料提供了任务背景，但其中要求沿用旧等级的文字不作为本轮执行指令。本轮不预设等级数量或名称，也不将新的字段组合包装成论文定论。当前真实 Runtime 仍为 `external_action=none`；真实付款、外发、生产提交等只作为待设计场景。原有来源确认、只读 Worker 派发和逻辑成果恢复的合同，不因研究文档而改变。

## 2. 最重要的反例

N04 的 113 人模拟研究中，POLICY 比逐动作 HITL 少拦截 20.1 个百分点的越界动作，95% CI 为 [-32.1, -8.1]。提示数从 18.0 降至 10.9，但计入规则配置后的总干预时间未可靠降低。对 AUTO 的差异在多重比较校正后不再可靠，不能只摘摘要里的未校正区间。[Ting Yan，§7–9](https://arxiv.org/html/2608.27443v1)

这不是“授权规则必然失败”：实验只用四个粗类别、固定脚本与无真实后果的短时场景，且后期补充了仅 POLICY 的样本。其限制提示我们应测试更细的对象/目的条件，而非宣称已经优于原方案。大多数越界是在用户批准后发生；不能把“已有人点同意”当作有效控制的充分证据。[同文方法与局限](https://arxiv.org/html/2608.27443v1#S9)

## 4. 应保留的事实，而非新的等级表

以下是综合推导的**待评审数据设计**，不是论文直接给出的 schema，也不是当前 API 字段清单：

| 独立事实 | 需要回答 | 为什么不能被一个风险颜色代替 |
| --- | --- | --- |
| 任务与委派合同 | 用户到底要什么；允许哪个子目标；谁可再委派 | 一项动作有用，不代表属于原目标 |
| 硬权限与策略 | 谁能对哪个对象做哪个动作；哪些行为明确禁止 | 即使预计后果小，用户也可能没有授权资格 |
| 证据与必要输入 | 结论有无依据；关键参数是否明确 | 证据充分不能替代动作许可；获准也不能补全事实 |
| 影响与可逆性 | 涉及谁；可恢复的确切对象和条件是什么 | 本地副本、原件、外部承诺的恢复能力不同 |
| 授权适用性 | 预览对象/参数/版本/期限是否仍匹配 | “刚才同意”可能针对旧收件人或已过期操作 |
| 运行和执行回执 | 未发起、已发起未知、已确认发生分别是什么 | 页面关闭、请求超时、撤销授权都不证明动作未发生 |
| 人的介入条件 | 谁负责；是否在线；何时可中断；延后意味着什么 | 不应由无人应答推导默认批准 |

风险标签仍可作为摘要或排序提示。这里反对的是把**粗粒度后果标签**当成唯一执行依据，并非数学上断言任何标量编码都无法携带多条件。尤其模型置信度只是一种不确定性线索，不是授权、业务核验或动作回执。

## 5. 推荐给沙盘的成对反例

下面的预期行为都是设计假设，应单独实现和验证；不触发实际外部动作。

| 配对情境 | 只改变的事实 | 候选交互与错误断言 |
| --- | --- | --- |
| 给同一内部团队生成摘要 / 将摘要发给外部联系人 | 接收对象与外部副作用 | 后者重新评估范围；不能沿用生成草稿的授权 |
| 允许发送给甲 / 待决后改为乙 | 被授权对象 | 作废旧动作预览；不是再展示相同“风险中”等级就继续 |
| 审批仍有效 / 审批已到期 | 期限 | 保留成果但停止新动作；超时不视为同意 |
| 有资源访问权 / 无资源访问权 | 硬权限 | 无权时拒绝或交给有资格的人；不能增加一次确认绕过 |
| 同一可靠引用 / 同一句有两个位置 | 证据位置 | 只核对该证据问题；不借机索取外发权限 |
| 可恢复副本编辑 / 已对外提交 | 可逆范围 | 前者可选恢复；后者只给已定义且验证的补偿路径 |
| 工具请求确定未发送 / 已发送但回执未知 | 执行事实 | 后者先对账；不直接宣称失败并重复执行 |
| 一个只读分支待核验 / 一个外部动作待批准 | Gate 类型 | 保留不受影响成果，分别显示采用问题和许可问题 |
| 用户拒绝 / 用户延后 / 用户关闭页面 | 决定语义 | 拒绝、尚未决定、记录失败分别保留，不把任一项写成同意 |
| 经验用户允许范围内连续推进 / 同用户发现方向错误 | 主动介入 | 仍可暂停和改范围，不能把事前授权变成放弃接管 |

“未知回执先对账”是本轮保守工程推导，**本轮未核验外部连接器的幂等、对账或补偿实现**。不是一概禁止任何网络重试：只有当执行端能证明安全重放，例如有效幂等键、同一动作参数和可靠回执查询，才可按该连接器合同重试。权限过期阻止未来动作，并不会撤回已发生效果。

## 6. 如何证伪候选方案

不要只演一个永远答对的授权沙盘。先比较完整交互模式，再视结果设计更干净的因子实验：

1. 完整界面对照：逐动作批准；粗类别持久规则；对象/参数/期限绑定的有界授权与异常请求。相同任务材料、动作序列和可见信息，明确任何无法保持一致之处。
2. 将正常动作、越权动作和证据不足动作分别计数；同时测必要任务完成、越界放行、漏拦截、误拦截。不能把阻止所有动作当安全赢家。
3. 记录规则配置、阅读、修改、重试和收尾的总时间，不能只计算运行时弹窗数。另测错误恢复成功与剩余任务状态理解。
4. 单独检验关键边界：对象改变、授权过期、硬禁令、未知回执和外部不可逆动作。每种界面都应允许拒绝、延后和主动中断。
5. 若要主张不降低安全或不降低完成率，需要预先规定非劣界值、样本量与统计方法；“差异不显著”不等于等效。
6. 主观控制感、信任和满意度单列，不能替代行为正确率。若新方案只少弹窗但多放行越界，就应否决或缩小适用范围。

上述为建议研究方案，不是已完成的用户实验。当前离线页面即使所有脚本断言通过，也只证明预设状态转移符合代码，不能证明用户理解或真实外部执行安全。
