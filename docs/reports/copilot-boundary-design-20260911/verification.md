## 4. 主动发现的具体问题

1. 初始 changed 情境把 v3 文件放入了“v2 已确认”的初始授权，叙述不一致。在首次浏览器测试前修正为先对 v2 建立模拟确认，再改变到 v3。
2. 初版只比较当前范围是否匹配，收件人改走再改回来使原确认复活。新增反例先红后绿；范围变动现在显式撤销旧确认，恢复原值也必须重新核对。
3. 已用于一次提交或已取消动作的确认不能继续显示可用，补充消费/撤销与状态文案；情境列表重绘恢复该按钮焦点。最终 UI 修订尚未浏览器复验。

## 5. 研究核验与边界

研究子任务实际打开每项原始页面/全文/官方文档，逐项记录阅读范围；N02 会议 PDF 失败，详细论点归属相关预印本而非假装已读会议版。N06/N07 为滚动文档，AP2 main 源码未冻结 commit，正式实现前需重新固定版本。

主任务另打开 N01/N04 的 arXiv 摘要和全文页面、N03 官方文章、N02 出版页、N05 规范、N07 checkpoint 文档，交叉核对主要结论。没有新增用户实验、SDK 执行或论文统计复现。子任务 201 项数据断言只证明本地台账结构，不替代联网阅读记录；可重复源码检查见 `verify.cjs` 及其 `static-verification.json`。

本原型不具备真正的异常检测或安全策略执行。没有模型调用、真实外部动作、数据库恢复、并发授权或真实 Connector 对账。已有 Q-01 内容完整性问题未修复。设计状态保持 `Draft`，浏览器、状态和用户效果三类证据不能混为一谈。
