# 用户理解测试：先复述，再操作

日期：2026-09-12。状态：待开展。尚未招募参与者，没有用户答案、通过率或效果结论。

本协议用于 [离线原型](index.html)，不是对真实外发系统的安全测试。主持人须先确认浏览器允许正常访问；不能绕过浏览器策略。所有邮件、数字、文件与权限均为演示数据。

## 目标与对象

拟面向日常整理周报、核对数据、与客户沟通的办公人员，优先邀请没有参与本原型设计的人。不同经验分别记录，不把研发人员的熟练操作当成普通用户可理解性。

本轮是形成性问题发现，不是证明效率提升的对照实验。先用少量自愿参与者试访，修复关键误解，再使用未看过原题的新参与者复测；具体人数、角色和顺序在招募前登记。不能凭“测过几个人”声称问题已找全。

## 主持方法

1. 征得参与同意；用匿名编号，不记录客户邮箱、真实周报或其他业务隐私。录音需另行明确同意。
2. 只说明“这是周报任务的演示，不会发送真实邮件”。先不解释确认、权限、接管、回执的区别。
3. 每轮从目标情境重置开始，隐藏测试设置、验收答案和主持人判定点。记录使用的页面版本、视口和任务顺序。
4. 在点击前问“现在发生了什么？你准备怎么做？预计点击后会怎样？”逐字记录第一回答和实际操作，不先讲正确答案。
5. 点击后问“现在有哪些变化？什么还没完成？”若误解，先记录，再允许中性追问“你是从哪里判断的？”不要问“你知道这还没发送吧？”
6. 需要提示才能继续时记录提示原话及次数；辅助后完成不能算独立完成。遇到困惑可暂停或退出，不计为使用者能力不足。
7. 所有首次观察结束后才讲解区别；同一参与者学过答案后的表现单独标注，不作为新设计独立可理解的证据。

## 五项核心任务

| ID | 主持人布置的目标与停顿点 | 非诱导提问 | 判定关键点，仅主持人阅读 |
| --- | --- | --- | --- |
| U1 | 请准备把当前周报交付给所列客户；第一次确认后停顿 | 现在发生了哪些事？接下来你会怎么做？ | 确认了附件和对象，尚未发送；演示尝试 0 次，真实邮件也没发出 |
| U2 | 打开发送结果未知情境；一次查询设为失败，再查询无记录 | 你认为任务到了哪一步？你会如何处理，为什么？ | 可能已发出，未知不是失败/未发送；查同一次记录，不重复发；查不到也不能断言没发 |
| U3 | 周报这次只报告“完成引导后的表现”；采用数据后停顿 | 刚才改变了什么？下一步继续写周报，你会找哪一份？ | 选 92%，保留引导后限定；当前 v3、历史 v2；没有外发许可或发送 |
| U4 | 打开未经批准折扣情境，保留内部草稿后停顿 | 接下来你会怎样使用这份草稿？还有谁需要做什么？ | 承诺内容仍在，需有权者审查；内部留档不等于修复或批准，不能直接发给客户 |
| U5 | 打开暂停情境，目标是让 Agent 继续处理交付 | 你会选哪个操作？预计系统接下来会怎样？ | 继续处理不是已经人工完成；邮件仍要确认，不自动发送，其他成果保留 |

补充迁移题：U1 之后换收件人，再换回原值，问“现在能否沿用刚才的决定，为什么？”；U3 中选择稍后决定，问“暂时离开后，这项任务会怎样？”补充题不得替代首次核心题。

## 记录和判定

[空白 CSV](comprehension-observations.csv) 只有表头，没有伪造参与者或答案。每个任务记录一行：第一回答、预计后果、实际操作、是否求助、错误理解、最后结果。耗时分别记阅读、操作和帮助，不用总时间掩盖误解。

每项采用 `独立理解 / 提示后理解 / 仍有误解 / 未完成观察`，并保留原话。下面任一关键误解出现，该用例必须回到设计迭代，不能被其他成功题或较短耗时抵消：

- 将确认、选择数据、继续处理当作已经发送或取得发送权限。
- 将结果未知或查不到记录当作未发送，并选择重复发送。
- 认为内部草稿已删除未经批准的承诺，或认为取消等于撤回已发送邮件。
- 报告 92% 时丢掉“引导后”条件，或把旧稿 v2 当成刚更新的当前稿。

这是候选设计验收门，不是经过统计验证的行业阈值。即使没有观察到这些误解，也只能描述本次样本、任务和版本，不能声称所有用户都看懂。

## 与自动化分开

`model.test.cjs` 验证合成状态转换；`presenter.test.cjs` 验证业务文案和按钮与该状态一致；Playwright 验证页面交互和布局；以上都不回答参与者是否理解。另一个 Agent 的源码走查同样不是目标用户访谈。
