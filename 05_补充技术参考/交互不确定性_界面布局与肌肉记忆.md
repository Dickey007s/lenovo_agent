# 交互不确定性深化调研：界面布局多变与肌肉记忆

## 1. 问题界定

在生成式 UI 中，系统会根据任务、上下文、用户画像或模型推理结果动态改变界面结构。这种能力提升了界面表达力，但也带来一个核心风险：**交互不确定性**。其中最典型的一类，就是**界面布局多变，导致用户难以形成稳定的空间记忆、操作习惯和肌肉记忆**。

这里的“肌肉记忆”并不只是字面上的手部动作记忆，更准确地说，是三类能力的叠加：

- **空间记忆**：用户记得控件“在哪里”。
- **习惯化反应**：用户在稳定情境下形成自动化选择。
- **运动程序**：用户无需重新搜索，就能快速完成点击、滑动、手势或快捷操作。

当生成式 UI 频繁改变按钮位置、区块层级、入口顺序、主次关系甚至标签语义时，用户每次都要重新搜索、重新判断、重新确认，这会直接削弱专家效率，也会破坏长期使用中的熟练度积累。

## 2. 为什么布局多变会伤害肌肉记忆

### 2.1 空间记忆依赖稳定位置

HCI 领域对空间记忆已有较强共识。Scarr、Cockburn、Gutwin 在 2013 年的综述中指出，用户可以通过记住控件的空间位置来实现流畅交互；但很多现代界面会通过移动或重排项目，破坏这种能力。[Supporting and Exploiting Spatial Memory in User Interfaces](https://www.nowpublishers.com/article/Details/HCI-046)

这意味着，**稳定布局本身就是一种性能资产**。一旦位置不断变化，用户就不能再“直接去拿”，而必须重新执行视觉搜索。

### 2.2 习惯形成依赖稳定情境

Garaialde 等人在 2020 年发表的研究明确量化了这一点：当用户在稳定界面中逐渐形成交互习惯时，选择速度和准确率都会提升；而一旦界面变化打断这种习惯，之前的性能收益会被显著削弱，甚至被完全消除。[Quantifying the impact of making and breaking interface habits](http://hdl.handle.net/10197/30899)

对生成式 UI 来说，这个结论非常关键。因为生成式系统如果每次都重新编排布局，就可能让用户永远停留在“重新适应”的状态，无法进入真正的熟练使用阶段。

### 2.3 运动线索和身体线索会帮助记忆

Tan 等人在 CHI 2002 的研究表明，带有直接身体线索的交互会增强空间记忆；他们报告触摸交互相较标准鼠标带来了 19% 的空间记忆提升。[Kinesthesis Cues Aids Spatial Memory](https://www.microsoft.com/en-us/research/publication/kinesthesis-cues-aids-spatial-memory/)

这说明“记住界面”并不只是认知问题，也和动作轨迹、身体感知有关。  
因此，如果生成式 UI 连控件相对位置和动作路径也不断变化，它伤害的不是单一视觉习惯，而是整套感知-动作回路。

### 2.4 专家效率建立在稳定映射之上

Kurtenbach 与 Buxton 在 CHI 1994 的 marking menus 研究展示了一个经典事实：稳定的方向-命令映射可以让用户从“看菜单选择”过渡到“直接画手势调用”；研究中，标记操作平均比菜单选择快 3.5 倍，且专家用户会大量使用这种快速路径。[User Learning and Performance with Marking Menus](https://www.billbuxton.com/MMUserLearn.html)

这给生成式 UI 一个很直接的启发：**如果界面想支持专家化，必须保留一层稳定映射**。没有稳定映射，就没有真正意义上的专家路径。

## 3. 相关实证研究：对“布局多变”的直接证据

| 研究 | 时间 | 关键发现 | 对生成式UI的启发 |
|---|---:|---|---|
| Scarr, Cockburn, Gutwin | 2013 | 空间记忆能显著支持流畅交互，移动或重排会破坏这种能力 | 生成式布局不能无限重排，应保护稳定空间锚点 |
| Findlater & McGrenere | 2004 | 在静态、可自定义、自动自适应菜单的对比中，静态菜单显著快于自适应菜单；多数用户总体更偏好可自定义方案 | 用户可控的变化通常优于系统强制变化 |
| Gajos et al. | 2008 | 自适应 UI 的可预测性和准确性都会显著提升满意度；准确性对性能和使用率影响更强 | 变化不是绝对不能做，但必须高准确、高可解释 |
| Findlater et al. | 2009 | “Ephemeral adaptation” 通过临时显著化预测项来提升效率，同时保持空间一致性；高准确率时快于静态菜单 | 最好的动态性常常不是“搬动控件”，而是“引导注意力” |
| Garaialde et al. | 2020 | 习惯形成会提高速度与准确率，但一旦界面变化打断习惯，收益会被消除 | 高频任务场景应尽量减少布局漂移 |
| Gaspar-Figueiredo et al. | 2026-01 | 一项 40 名参与者、20 种自适应菜单的研究显示：所有图形自适应菜单都比静态菜单带来更高的认知负荷和记忆负担，但某些方案在吸引力与效率上有优势 | 动态界面会引入认知税，不应把“变化”视为零成本 |

## 4. 对生成式UI的核心风险判断

把这些文献放到生成式 UI 场景里，可以得到比“布局别乱变”更细的四个判断。

### 4.1 最大的问题不是“变化”，而是“变化不可预期”

如果布局变化遵循稳定规则，例如：

- 始终在同一主区域内重排
- 始终保留主操作区不变
- 始终把变化限制在低风险内容区
- 始终可以由用户 pin 住常用入口

那么用户仍有机会建立高层次规则记忆。  
真正破坏体验的是**每次生成都像新界面**，并且用户无法预测“哪个区域会变化、哪个动作会挪位、哪个按钮会改名”。

### 4.2 对专家用户的伤害大于对新手用户

新手本来就依赖搜索，所以布局变化对他们的边际伤害有限。  
专家用户则依赖熟练路径、固定手势、稳定热点和快速定位，因此布局漂移会直接抹掉他们积累出来的效率优势。

这意味着生成式 UI 在首次体验上可能显得“聪明、灵活”，但在高频长期使用里，反而可能因为失去熟练路径而变慢。

### 4.3 高风险操作最怕位置漂移

当“删除、提交、支付、发送、确认审批”这类动作的位置和邻近关系变化时，用户很容易因为旧习惯而误操作。  
因此，生成式 UI 最大的不确定性风险，不是视觉审美不稳定，而是**动作语义与空间位置的绑定被打断**。

### 4.4 最容易被接受的动态性，是“强调变化”，不是“结构迁移”

Findlater 等人在 2009 年的结果很有启发性：通过临时显著化预测项而不是直接重排位置，可以兼顾效率和空间一致性。  
这说明对生成式 UI 来说，更优的路线通常不是“把最重要按钮重新搬到别处”，而是：

- 高亮
- 放大
- 延后出现次要项
- 暂时提升视觉优先级
- 在稳定槽位中替换内容

也就是让**注意力流动**，而不是让**布局漂移**。

## 5. 哪些变化最伤肌肉记忆，哪些还能接受

### 5.1 高风险变化

- 高频操作按钮跨区移动
- 主次操作左右互换
- destructive action 与 safe action 的相对位置变化
- 同一语义动作在不同轮次使用不同标签或图标
- 每次生成都重新组织导航层级
- 快捷键、手势、浮动入口频繁重映射
- 用户已使用多次的流程在跨会话中被整体改写

### 5.2 相对可接受的变化

- 内容在稳定槽位中更新
- 次要区域的展开/折叠
- 同一区域内的排序微调
- 对推荐项做高亮而非搬移
- 仅在单次任务会话内做局部适配
- 用户主动触发或确认后的布局变化
- 低风险探索面板的动态生成

可以把这条原则概括为：  
**动作区要稳定，内容区可变化；锚点要稳定，细节可生成。**

## 6. 面向生成式UI的设计原则

### 6.1 建立“空间锚点层”

无论中间内容怎么生成，始终固定以下元素：

- 返回/退出
- 主导航
- 搜索/命令入口
- 主动作区
- 撤销/恢复
- 高风险确认位

这相当于给生成式 UI 加一层不会漂移的“骨架”。

### 6.2 为高频动作保留“运动常量”

高频动作不只要语义一致，还要位置一致、手势一致、调用路径一致。  
如果系统允许这些动作每次换位置，用户就无法形成真正的程序化操作。

### 6.3 让动态性主要发生在内容层，而不是动作层

推荐把生成能力主要用于：

- 内容摘要
- 信息组合
- 辅助解释
- 次要视图生成
- 工作区配置

而不是把关键按钮、流程顺序和确认路径每次都重新生成。

### 6.4 优先采用“提示型适配”而不是“重排型适配”

可参考 ephemeral adaptation 的思路：

- 高亮预测项
- 弱化次要项
- 先显示主项，再渐进显示长尾项
- 在原位置上做视觉权重调整

尽量不要直接改变控件物理位置。

### 6.5 变化应尽量用户可控

Findlater 与 McGrenere 的结果很适合生成式 UI：  
比起系统自动改布局，用户通常更接受自己控制或确认后的变化。

因此可以加入：

- pin 常用组件
- 锁定当前布局
- 记住我的工作区
- 只在本会话临时优化
- 显示“按你的习惯固定此区域”

### 6.6 支持“从新手到专家”的双通道

好的生成式 UI 不该只有一条“每次都让模型生成”的路径，还应支持：

- 稳定命令面板
- 固定快捷键
- 固定手势
- 可收藏动作
- 常用流程一键复现

也就是说，系统既要能生成，也要能沉淀。

## 7. 适合后续研究的评测指标

如果把“布局多变导致肌肉记忆难形成”做成正式研究议题，建议重点测以下指标：

| 指标 | 说明 |
|---|---|
| 布局漂移率 | 相邻轮次中关键控件位置变化比例 |
| 锚点稳定率 | 主导航、主动作区、高风险动作区是否保持稳定 |
| 重定位时间 | 布局变化后重新找到目标控件所需时间 |
| 习惯破坏成本 | 布局变化前后任务时间、错误率、犹豫时间的增量 |
| 空间回忆准确率 | 用户是否能回忆目标控件位置 |
| 专家路径采用率 | 快捷路径、固定入口、手势是否被持续使用 |
| 可预测性感知 | 用户是否能预期界面下一步如何变化 |
| 信任与控制感 | 用户是否感到界面“可靠”“可掌控” |

## 8. 对当前生成式UI研究的一个关键补充判断

此前我们讨论生成式 UI 时，重点更多放在协议栈、布局生成能力和动态编排能力上。  
这轮调研补充了一个同样重要但更偏长期使用的问题：

**生成式 UI 不能只优化“这一轮最合适的界面”，还必须优化“多轮使用后仍能被熟练掌握的界面”。**

换句话说，生成式 UI 的能力上限不只取决于它会不会生成，而取决于它能不能在动态性和稳定性之间找到边界：

- 该变的地方可以变
- 不该变的地方不能变
- 变化最好可解释、可预测、可回退、可固定

如果这一点做不好，生成式 UI 很容易在“首次体验更聪明”和“长期使用更费脑”之间失衡。

## 9. 结论

围绕“交互不确定性：界面布局多变，用户难以形成肌肉记忆”这一点，现有 HCI 研究给出的信号其实相当一致：

- **空间记忆是高效交互的基础能力。**
- **稳定情境会形成习惯，习惯会显著提升速度和准确率。**
- **一旦界面频繁变化，这些收益会被明显削弱。**
- **动态界面的更优方向，不是频繁搬动控件，而是在稳定骨架上做局部生成与注意力引导。**

因此，对生成式 UI 来说，真正成熟的设计目标不应是“让界面每次都更会变”，而应是：

**在可生成的内容层之上，保住可学习、可预测、可熟练的交互层。**
